# 04. Формат CSV с точками

## 1. Назначение

CSV — промежуточное представление массива точек между разбором траектории и
EGM-клиентом. Файл человекочитаемый, его можно открыть в Excel и глазами
проверить, что траектория разобрана правильно.

## 2. Формат записи

```
index,x,y,z
1,750.000000,0.000000,600.000000
2,850.000000,0.000000,600.000000
3,850.000000,100.000000,600.000000
4,750.000000,100.000000,600.000000
```

* `index` — номер точки, начиная с **1** (просто для чтения, в расчётах не участвует);
* `x, y, z` — абсолютные координаты в миллиметрах, 6 знаков после точки;
* разделитель — запятая, конец строки — `CRLF` (совместимо с Excel и «Блокнотом»);
* кодировка — ASCII/UTF-8 без BOM (заголовок латиницей, поэтому проблем нет);
* исторический `data/points_selftest.csv` содержит Z=300, рабочие файлы (`trajectory.gcode`, `points.csv`) — Z=600.

Запись выполняет `WritePointsCsv()` (`src/csv_io.cpp`), формат числа —
`"%.6f"` в C-локали, поэтому десятичный разделитель всегда точка, независимо от
региональных настроек Windows.

## 3. Правила чтения (устойчивость)

`ReadPointsCsv()` намеренно терпим к «чужим» файлам:

| Ситуация | Поведение |
|---|---|
| заголовок `index,x,y,z` | пропускается (первое поле не число) |
| разделители `,` `;` табуляция | поддерживаются |
| 4 числовых колонки | трактуются как `index, x, y, z` |
| 3 числовых колонки | трактуются как `x, y, z` |
| пустые строки, `\r`, BOM UTF-8 | игнорируются |
| мусорные строки | пропускаются |
| ни одной точки | ошибка «в CSV-файле не найдено ни одной точки» |

Координаты читаются `strtod` (C-локаль), поэтому `1,5` как «полтора» не
поддерживается — только `1.5`. Это осознанно: так файл одинаково читается на
машинах с русской и английской локалью.

## 4. Как получить файл

1. В приложении: «Открыть файл…» → выбрать `.gcode` → «Сохранить CSV…».
2. Без GUI: `FrezaEgm_selftest.exe <файл-траектории> <выходной-csv>` —
   самотест попутно записывает CSV (так получен `data/points.csv`). Без второго
   аргумента файл пишется во временный каталог Windows.
3. Вручную — формат настолько прост, что файл можно набрать в блокноте.

## 5. Ограничения

* Нет колонок ориентации (`rx, ry, rz`) — ориентация пока не управляется.
* Подача (`F`) из G-code не читается; темп задаётся в приложении шагом и скоростью (мм/с).
* Нет единиц измерения в файле: подразумеваются миллиметры.
