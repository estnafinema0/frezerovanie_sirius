# STEP → заготовка → черновая → чистовая

Реализация в ветке `feature/stock-roughing`, поверх `feature/bezier-viewer`.
Это офлайн-программа **одной установки сверху** для одного замкнутого STEP solid.
Программа содержит операции, переходы, XYZ/quaternion и общую шкалу времени.
Она не объявляет произвольную деталь полностью изготовленной: исключённые грани,
невыбранный остаток и обнаруженные пересечения входят в отчёт.

## Что взято из обсуждения и MD

Прочитаны [общий чат «Алгоритм нормали поверхности»](https://chatgpt.com/share/6b03e037-220c-83ed-b4ee-2778bb19847f?ogimg=plain)
и переданный `robot_milling_project_handoff.md` (разделы 4–6, 8, 13–17).
В чате описан геометрический прототип и предложен Qt/OCCT viewer; MD дополнительно
задаёт stock block, Z-слои, припуск и учёт снятого материала.

| Часть | Реализация |
|---|---|
| STEP/B-rep/единицы | OCCT 7.9.3, миллиметры, настоящие грани и trim |
| Черновая | Горизонтальные Z-слои, raster/zigzag, вертикальная фреза, защита целевой детали с припуском |
| StockDefinition / StockModel | Явный блок; ограниченная сетка колонок и обновляемая высота остатка |
| MaterialRemoval | Съём по swept XY capsule; повторный проход не удаляет уже снятый объём |
| Чистовая | Существующий адаптивный raster по CAD-поверхности: D1, нормаль, XYZ/quaternion, trim |
| Без осевого spin | Начальная касательная + минимальный поворот между нормалями; это уточнение пользователя к исходной формуле X по подаче |
| Общая программа | Все черновые операции перед чистовыми, переходы на высоте, единая нумерация и время |
| Проверка остатка | После черновой — колонки; при чистовой — voxel replay цилиндра с неизменяемой маской STEP solid |
| Просмотр | Сохранён запрошенный браузерный интерфейс C++/Canvas; перенос на Qt не нужен для математического расчёта |
| Робот | Защищённый EGM не меняется. IK, держатель, крепления и реальный Force Control не считаются реализованными |

## Запуск на Windows

Нужны Git, CMake ≥3.21, Visual Studio 2022 с C++ и Windows SDK. Python 3 — для
HTTP/UDP-тестов, не для запуска приложения.

```powershell
git status --short
git fetch origin
git switch feature/stock-roughing
git pull --ff-only origin feature/stock-roughing
cmake -P MillingAnalyzer/cmake/Dependencies.cmake
$deps = Join-Path $pwd 'build-bezier-viewer-deps'
cmake -S MillingAnalyzer -B build-bezier-viewer -G "Visual Studio 17 2022" -A x64 "-DCMAKE_PREFIX_PATH=$deps/occt" "-DEIGEN_INCLUDE_DIR=$deps/eigen"
cmake --build build-bezier-viewer --config Release --parallel 4
ctest --test-dir build-bezier-viewer -C Release --output-on-failure
.\build-bezier-viewer\Release\MillingAnalyzer.exe
```

Сначала сохраните/разберите свои изменения, если `git status` не пуст; не применяйте
`reset --hard`. Зависимости те же: OCCT 7.9.3 и Eigen 3.4.0, закреплённые commits в
`MillingAnalyzer/cmake/Dependencies.cmake`. Новая Protobuf-библиотека не используется.

В готовом CI-архиве запустите `build-bezier-viewer/Release/MillingAnalyzer.exe`,
сохранив все DLL рядом. Файлы STEP можно хранить в любой папке, включая пути с
пробелами/Unicode: в интерфейсе выберите файл, копировать его внутрь приложения не нужно.

## Работа в интерфейсе

1. Нажмите **«Открыть STEP / STP…»** и выберите свой файл либо перетащите его в окно.
   Поддерживаются `.step`/`.stp` (регистр расширения не важен), пути с пробелами и Unicode,
   до 50 MiB. Имя, единицы и габариты показаны над параметрами. Импорт показывает
   модель, но не запускает расчёт или движение. При смене файла заготовка, выбор
   чистовых граней и подтверждение врезания сбрасываются; старый пример не используется.
   Повторный выбор того же файла также выполняет импорт. При ошибке прежний результат сохраняется.
2. Выберите стратегию: **Чистовая · выбранная грань**, **Черновая · Z-слои** либо
   **Программа · черновая + чистовая**.
3. Для черновой/программы задайте X/Y/Z min/max блока в системе детали, глубину
   слоя, шаг проходов, припуск, размер ячейки и подачу. Кнопка «Пример блока по
   габаритам» даёт только пример для просмотра, не измерение настоящей заготовки.
4. Подтвердите, что фреза допускает осевое врезание. Без подтверждения расчёт
   черновой отклоняется. Демонстрационные режимы не являются рекомендациями резания.
5. В «Чистовые грани» укажите `auto` для всех верхних граней либо номера через запятую.
   Непригодная явно выбранная грань вызывает понятный отказ всего нового расчёта.
6. Нажмите «Рассчитать». В списке модели появится «Программа», в списке траектории —
   вся программа, Z-слои и чистовые грани. Операции являются срезами общей программы:
   их ориентации и проверки не расходятся с общим воспроизведением.
7. Сравните «После черновой» / «После всей программы»: жёлтые точки показывают
   верхнюю оболочку остатка. Она не изображает внутренние полости voxel-модели.
8. Посмотрите объёмы, исключённые грани, красные столкновения. Экспортируйте JSON
   и `program.poses.csv` для офлайн-проверки. Этот CSV **не** загружается в FrezaEgm
   и не принимается прежним виртуальным адаптером поз.

Примеры находятся в раскрываемом разделе **«Встроенные примеры»**.
Сохранённый `preview.html` служит только для просмотра результата; загрузка новых
STEP работает на странице запущенного `MillingAnalyzer.exe`, а не в статическом HTML.

Кнопка **«Ступень · программа»** создаёт синтетический пример с явно заданным
блоком и допущением о фрезе с центральным резанием. Это не параметры вашего стенда.

## Контрольный STEP и CLI

`MillingAnalyzer/data/stepped-solid.step`: объединённые прямоугольные тела,
основание 20×20×2 мм и ступень 10×20×2 мм. Исходная геометрия воспроизводится
функцией `programDemo()`; тестовый исполняемый файл также умеет записать её в STEP.
Пользовательские CAD-модели в GitHub не публикуются.

```powershell
.\build-bezier-viewer\Release\MillingAnalyzer.exe MillingAnalyzer/data/stepped-solid.step --program --stock -2 -2 0 22 22 6 --confirm-centre-cutting --output program-preview --open
```

Результат: `preview.html`, `scene.json`, `program.poses.csv`, отдельные CSV чистовых
граней. Каталог должен быть новым: существующий результат не перезаписывается.
Для одной черновой используйте `--rough-only` вместо `--program`.
Параметры: `--step-down`, `--rough-spacing`, `--allowance`, `--stock-cell`,
`--rough-feed`, прежние `--diameter`, `--length`, `--step`, `--feed`, `--chord`,
`--angle`. `--face ID` ограничивает чистовую одной гранью.

Схема CSV программы:

```text
stage,operation,sample_id,part_x_mm,part_y_mm,part_z_mm,qw,qx,qy,qz,time_s,motion,collision,sweep_collision
```

stage: 1 черновая, 2 чистовая. motion — сегмент, заканчивающийся в данной позе:
0 резание, 1 отвод, 2 переход, 3 подвод без резания, 4 врезание с подачей.
Quaternion w,x,y,z — активное вращение tool→part. Координаты пока в детали,
не в базе ABB. TCP offset не прибавляется. JSON явно содержит `robotReady:false`.

## Математика черновой и остатка

Блок задаётся двумя углами. XY разбивается на ячейки; каждый треугольник CAD-сетки
обрезается прямоугольником ячейки. `target[i]` — максимум Z всех полученных
вершин. Это верхняя оболочка **всей** модели, а не прямоугольник её bbox.
Скрытые под нависанием полости из этой установки не выбираются.

Уровни идут от верха блока вниз с шагом не больше `stepDown`. Для каждого
растрового отрезка проверяется swept footprint цилиндра — капсула радиуса R.
Для защиты модели footprint расширяется на припуск и половину диагонали ячейки.
Нельзя опуститься ниже `target + allowance + 0.03 mm`. 0.03 мм — явный запас к
сетки OCCT с deflection 0.02 мм; это не математическое доказательство точности
тесселяции любой NURBS.

Остаток моделируется высотами в центрах ячеек. Под капсулой высоты уменьшаются
до Z фрезы; объём суммируется как `dx*dy*(oldZ-newZ)`. Он не вычитается повторно.
Пустые участки пропускаются, доступная глубина врезания в материальных samples
ограничена `stepDown`. Смежные отрезки связываются на уровне слоя, если защищённая
модель не пересекается и глубина допустима; иначе следует подъём над блоком.
Во время черновой инструмент вертикален, поэтому для холостого перехода хватает
`stockTop+clearance`. Перед наклоном для чистовой поднимаемся выше с учётом полной
длины цилиндра. Осевое врезание ограничено min(2 мм/с, заданная подача).

После черновой колонки преобразуются в ограниченную voxel-сетку. Для чистовой
проигрываются исходные и промежуточные XYZ+SLERP-позы. Материал внутри цилиндра
удаляется только на режущих сегментах; на холостых пересечение отмечается ошибкой.
`BRepClass3d_SolidClassifier` защищает центры voxels внутри целевого solid от
удаления. Дополнительно вся собранная траектория проверяется против CAD-сетки,
включая промежуточные положения, переходы и врезания. Объёмы после чистовой и
остаток являются оценками с разрешением заданной ячейки, а не точным Boolean solid.

## Область применимости и проверки

Поддерживается одна установка сверху, один closed solid, до 32 граней, блок до
200 мм по сторонам и до 30 мм высотой, глубина в пределах заданной длины фрезы.
Ограничены колонки, voxels, сканирование, точки и число collision-запросов.
Отдельная чистовая открытой Bezier-поверхности остаётся доступна в прежнем режиме;
её нельзя молча принять за замкнутую деталь для объёмной черновой.

Ненулевой остаток не объявляется обработанным. Узкие углы, боковые/нижние грани,
держатель, крепления, переустановки, точный scallop/остаток, кинематика и ограничения
ABB требуют последующих стратегий и проверок. Ускорения и силовая нагрузка не
моделируются. «Полная программа» в интерфейсе означает объединение выбранных
операций этой установки, а не подтверждение изготовления любой STEP-детали.

CTest `milling_program`: двухуровневая целевая геометрия, сохранение объёма,
отсутствие повторного съёма, глубина/порядок слоёв, zigzag, защита промежутка между
концами отрезка, припуск, постоянная черновая ориентация, временная последовательность,
остаток после чистовой, запрет неизвестной заготовки/врезания/нечисловых параметров.
HTTP-тест проходит путь импорт STEP → общая программа и проверяет сохранение модели
при ошибке. Прежние geometry/Bezier/trim/quaternion-тесты и protected baseline сохранены.
Windows CI собирает также FrezaEgm CAM ON/OFF и запускает прежний UDP-loopback.
RobotStudio и физический ABB здесь не запускались.
