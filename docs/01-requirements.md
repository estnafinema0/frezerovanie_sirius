# 01. Требования

## 1. Назначение

Приложение **FrezaEgm** управляет фрезерующим манипулятором ABB IRB 1600 по
технологии ABB EGM (Externally Guided Motion): получает траекторию из файла,
превращает её в последовательность точек, сохраняет их в CSV и передаёт на
контроллер (в симуляции — в RobotStudio) в виде protobuf-сообщений `EgmSensor`.

## 2. Исходная постановка (из задачи)

1. Получить файл с траекторией (минимальный пример — замкнутый квадрат 100×100 мм, 5 точек).
   Определить формат, совместимый с конвертацией STL → траектория.
2. Передать файл разрабатываемой программе.
3. Получить из траектории массив координат и сохранить в CSV.
4. Прочитать CSV и сгенерировать управляющие EGM-сигналы.
5. Сериализовать сигналы в protobuf 3 и отправить в RobotStudio для симуляции.

## 3. Границы

**Входит в объём:**

* разбор G-code (подмножество) и простого формата `x y z`;
* запись/чтение CSV с точками;
* EGM-клиент: UDP, protobuf (nanopb), цикл «принять → ответить», журнал;
* GUI: загрузка файла, сохранение CSV, запуск/остановка траектории, ручные команды;
* самотест без робота (UDP-loopback);
* документация и инструкция по RobotStudio.

**Не входит (сознательно):**

* конвертация STL → G-code (делается внешним CAM, см. `03-trajectory-format.md`);
* управление ориентацией инструмента (`orient`/`euler` не передаются);
* интерполяция между точками и планирование скоростей;
* дуги G2/G3 (берётся только конечная точка);
* работа с реальным контроллером по сети (только 127.0.0.1 / локальная сеть без защиты);
* аутентификация и шифрование EGM (в протоколе их нет).

## 4. Пользовательский сценарий

1. Технолог готовит `trajectory.gcode` в CAM (или вручную — 5 точек).
2. Оператор запускает RobotStudio, включает виртуальный контроллер, запускает
   RAPID-программу `ModuleEGM` — робот встаёт в первую точку и вызывает `EGMRunPose`.
3. В приложении нажимает «Запустить траекторию»: приложение занимает UDP-порт 6510,
   ждёт первый пакет `EgmRobot`, затем отправляет `EgmSensor` с абсолютной позой
   первой точки и далее — по точкам.
4. Робот проходит ломаную; в окне видно номер точки, счётчики пакетов, состояние
   MCI/моторов и обратную связь.
5. «Стоп» останавливает поток; RAPID по таймауту завершает сессию.

## 5. Функциональные требования

| ID | Требование | Реализация |
|---|---|---|
| FR-1 | Загрузка файла траектории с автоопределением формата (G-code / XYZ) | `LoadTrajectory`, `DetectFormat` |
| FR-2 | Показ количества точек и предупреждений парсера | GUI, поле «точек: N», журнал |
| FR-3 | Сохранение точек в CSV `index,x,y,z` | `WritePointsCsv` |
| FR-4 | Загрузка CSV как источника траектории | `ReadPointsCsv` |
| FR-5 | Запуск EGM-сессии: занятие UDP-порта 6510, ожидание пакета контроллера | `EgmClient::Start` |
| FR-6 | Отправка `EgmSensor` с `planned.cartesian.pos` = абсолютная поза TCP в базе, период 4 мс; темп задаётся шагом и скоростью | `EgmClient::Worker` |
| FR-7 | Приём и разбор `EgmRobot`, отображение MCI, моторов, сходимости, фактической позы | `ApplyRobot` |
| FR-8 | Журнал событий с отметкой времени | `AddLog`, `TakeLog` |
| FR-9 | Ручные команды: смещение dX/dY/dZ от стартовой точки, кнопка `Home` | GUI, `OnSendManualPoint`, `OnHome` |
| FR-10 | Остановка потока без закрытия приложения | `EgmClient::Stop` |
| FR-11 | Самотест без робота (файл → CSV → protobuf → UDP) | `FrezaEgm_selftest` |
| FR-12 | Понятные ошибки: занятый порт, нет пакетов, битый файл | тексты в `message` и журнале |

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Windows 10/11 x64, сборка MSVC (VS2022), без сторонних DLL |
| NFR-2 | Частота отправки ≥ 200 Гц (период 4 мс), запас по времени кадра |
| NFR-3 | Точность координат — `double`, вывод в CSV — 6 знаков |
| NFR-4 | Приложение не блокирует UI: сеть работает в отдельном потоке |
| NFR-5 | Журнал ограничен 800 строками, без утечек памяти |
| NFR-6 | Запуск приложения < 1 с, потребление памяти < 50 МБ |
| NFR-7 | Код собирается без предупреждений уровня `/W4` (наш код) |

## 7. Допущения

* Робот и ПК — одна машина (`127.0.0.1`); для реального контроллера адрес источника
  берётся из входящего пакета, поэтому менять код не нужно.
* Стартовая поза робота совпадает с первой точкой файла (RAPID: `MoveJ home`).
* Файл траектории задан в миллиметрах в системе координат базы (`base`).
* EGM-устройство в контроллере называется `EGMSensor` и смотрит на порт 6510.

## 8. Критерии приёмки

1. `FrezaEgm_selftest` завершается с кодом 0 и печатает «УСПЕХ» (35 проверок).
2. Файл `data/trajectory.gcode` даёт ровно 5 точек; CSV содержит 5 строк с теми же
   координатами.
3. При запуске с RobotStudio робот проходит замкнутый квадрат 100×100 мм (5 точек),
   в приложении растут счётчики отправленных/принятых пакетов.
4. Без RobotStudio приложение не «висит»: показывает «ожидание контроллера» и по
   таймауту — ошибку.
5. Повторный запуск после «Стоп» работает (порт освобождается).

## 9. Открытые вопросы

| # | Вопрос | Влияние |
|---|---|---|
| 1 | Доступен ли `EGMRunPose` в RobotWare 6.08 (станция из `.rspag` — под 6.13)? | Если нет — нужен `EGMRunJoint` и joint-режим в приложении |
| 2 | Нужна ли ориентация инструмента (фреза вдоль −Z, наклон)? | Потребует заполнения `orient`/`euler` и пересчёта позы |
| 3 | Нужна ли интерполяция и подача в мм/с? | Влияет на плавность и «фрезерность» движения |
| 4 | Нужна ли поддержка дуг (G2/G3) и спиралей? | Иначе траектория из CAM будет огрублена до отрезков |
| 5 | Нужен ли журнал EGM в файл (для отчёта)? | Сейчас журнал только в окне |
