# 09. Журнал технических решений

Записи в формате ADR (Architecture Decision Record): контекст → решение → следствия.
Дата — 2026-11-18, если не указано иное.

---

## ADR-001. nanopb вместо полного protobuf C++

**Контекст.** В `Egm/lib/protobuf_installed/lib` лежат `libprotobuf.a`,
`libprotobuf-lite.a`, `libprotoc.a` — сборки MinGW. Целевая среда — MSVC (VS2022).
MinGW-библиотеки в MSVC не линкуются (другой ABI и формат), а `protoc.exe` из
комплекта вообще не запускается без MinGW-DLL.

**Решение.** Использовать **nanopb** — C-реализацию protobuf с фиксированной
памятью. Сгенерированный код компилируется тем же MSVC.

**Следствия.**
+ Нет зависимости от бинарных библиотек и DLL; проект собирается «из коробки».
+ Размер и потребление памяти минимальны.
− Нет reflection/JSON/динамических сообщений (для EGM не нужны).
− Для `repeated` нужны `max_count` в `.options` (для EGM — 6).

**Альтернативы.** Собрать protobuf 3.7.1 из исходников под MSVC (долго, десятки
файлов, лишние зависимости) или взять vcpkg-пакет (требует установки).

## ADR-002. proto3 с `optional` для числовых полей

**Контекст.** У ABB в `egm.proto` (proto2) поля `EgmCartesian.x/y/z` объявлены
`required`. В proto3 по умолчанию поля со значением `0` не сериализуются, и
proto2-парсер контроллера получит сообщение без обязательных полей.

**Решение.** Схема `Egm/egm3.proto` — `syntax = "proto3"`, а «обязательные по
смыслу» числовые поля помечены `optional` (explicit presence). Клиент всегда
выставляет `has_x/has_y/has_z = true`.

**Следствия.**
+ Нулевые координаты уходят явно — совместимо с proto2-парсером ABB.
+ Схема остаётся в синтаксисе proto3, как требовалось.
− Нужен `protoc` ≥ 3.15 (проверено на 33.6); `protoc` 3.7.1 не подходит.

## ADR-003. Pose-режим EGM

**Контекст.** EGM умеет pose guidance (`EGMRunPose`) и joint guidance
(`EGMRunJoint`). Станция `SolutionEGM.rspag` использует `\Pose` и порт 6510.

**Решение.** Реализован pose-режим: передаём `planned.cartesian.pos`.

**Следствия.**
+ Совпадает с готовой станцией и с задачей («движение фрезы по точкам»).
+ Нет обратной кинематики на стороне ПК.
− Ориентация не управляется (см. ADR-013).

**Риск.** В RobotWare 6.08 может не быть `EGMRunPose` — тогда понадобится
joint-режим (см. `docs/06-robotstudio-setup.md`, §0).

## ADR-004. Абсолютные координаты TCP (пересмотрено)

**Контекст.** Сначала отправлялись смещения `p_i − p_0`, считая, что `EGMRunPose`
применяет коррекцию относительно позы в момент старта сессии. На практике робот
уезжал: цель `0,0,0` контроллер понимал как «TCP в начало базы».

**Решение.** Отправлять **абсолютную позу TCP** в базовой системе, потому что
`corr_frame` единичный и задан `EGM_FRAME_BASE` — система коррекции совпадает с базой.
Первая точка файла обязана совпадать с `home` (RAPID `MoveJ home`).

**Следствия.**
+ Робот идёт по траектории, а не «к себе и вниз».
+ Ручные команды и `Home` считаются как `base + d` и `base` соответственно.
− При смене файла первую точку и `home` нужно менять согласованно.

## ADR-005. Интерполяция и управление скоростью

**Контекст.** Без интерполяции робот прыгает между вершинами, подача не управляется.
С ожиданием каждой подточки движение получалось «стоп-разгон», а с переключением по
таймеру срезались углы.

**Решение.**
1. `InterpolatePath` режет путь на подточки с шагом `шаг` мм; время на подточку =
   `шаг / скорость`, вершины исходной траектории помечаются флагом.
2. На прямых участках цель движется по времени (непрерывно, без остановок).
3. На вершинах — короткая досылка (до `cornerSettleMs` = 700 мс), чтобы угол не срезался.
4. `\MaxSpeedDeviation:=1000.0` в `EGMActPose` снимает низкий лимит скорости
   контроллера — иначе поле «скорость» не влияет на движение.

**Следствия.**
+ Скорость регулируется (слайдер 5–200 мм/с), шаг меняет только гладкость.
+ Поле «держать точку» удалено вместе с режимом ожидания.
− При очень большом шаге траектория становится «гранёной».
− Точка расширения: генерация подточек с подачей мм/с (см. `02-architecture.md`, §7).

## ADR-006. GUI на Win32 API

**Контекст.** Нужно окно с кнопками и журналом; Qt в системе нет, ставить
сторонние библиотеки без согласия нельзя.

**Решение.** Чистый Win32 API (`CreateWindowExW`, стандартные контролы),
Unicode, шрифт Segoe UI, DPI-aware.

**Следствия.**
+ Ноль зависимостей, всё есть в VS2022.
− Больше кода, чем на Qt/ImGui, нет «красивостей».
− Точка расширения: заменить на Dear ImGui, если понадобится сложный UI.

## ADR-007. Формат траектории: G-code + «x y z»

**Контекст.** Из STL напрямую траекторию не получить, нужен CAM. Практически все
CAM выгружают G-code.

**Решение.** Парсер поддерживает подмножество G-code (G0/G1, G90/G91, G20/G21,
комментарии) и простой текстовый список `x y z`; формат определяется автоматически.

**Следствия.**
+ Совместимо с FreeCAD/Fusion/MeshCAM без конвертеров.
+ Для теста можно набрать 4 строки руками.
− Дуги (G2/G3) огрубляются до отрезков, циклы и коррекции игнорируются.

## ADR-008. CSV: `index,x,y,z`

**Контекст.** Нужен человекочитаемый промежуточный формат, совместимый с Excel.

**Решение.** Заголовок `index,x,y,z`, координаты с 6 знаками, `CRLF`, точка как
разделитель дробной части (C-локаль).

**Следствия.**
+ Файл открывается в Excel и легко проверяется глазами.
+ Чтение терпимо к `;`, табуляции, отсутствию индекса и заголовка.
− Нет ориентации и подачи (пока не нужны).

## ADR-009. Порт 6510 и ответ на адрес источника

**Контекст.** EGM-устройство `EGMSensor` в `SIO.cfg` смотрит на `127.0.0.1:6510`.
Отвечать нужно тому, кто прислал пакет.

**Решение.** Клиент биндит UDP `0.0.0.0:6510`, адрес назначения берёт из
`recvfrom` и отвечает на него.

**Следствия.**
+ Работает и в симуляции, и с реальным контроллером без изменения кода.
+ Не нужен отдельный параметр «IP робота» в интерфейсе.
− Порт фиксирован; при занятом порте — понятная ошибка Winsock 10048.

## ADR-010. CMake + MSVC вместо MinGW

**Контекст.** Старый проект собирался MinGW (`Egm/CMakeLists.txt`, `Readme.txt`).

**Решение.** Тот же CMake, но генератор `Visual Studio 17 2022` и компилятор MSVC.
`CMakePresets.json` оставлен для сборки из VS.

**Следствия.**
+ Единая среда с VS2022, отладка «из коробки», нет зависимости от MinGW.
+ Старые `.a`-библиотеки и `mingw.7z` больше не нужны.
− Сборка под MinGW теперь не поддерживается (при необходимости — отдельная цель).

## ADR-011. Стартовая точка (750, 0, 600), инструмент вниз

**Контекст.** Первая поза должна быть достижимой и не попадать в сингулярность.
При Z = 300 и ориентации `[0,0,1,0]` контроллер выдавал `50456 Close to singularity`.

**Решение.** Демо-траектория — замкнутый квадрат 100×100 мм на Z = 600 мм, первая
точка (750, 0, 600); `home` в RAPID совпадает с ней, ориентация `[0,1,0,0]`
(инструмент смотрит вниз), инструмент — `toolPencil` (TCP 280 мм).

**Следствия.**
+ Движение в знакомой зоне, сингулярности нет, легко увидеть в симуляции.
− Для другой детали нужно согласованно менять `home` и первую точку файла.

## ADR-012. Сгенерированный код хранится в проекте

**Контекст.** `egm3.pb.c/.h` можно генерировать при сборке.

**Решение.** Файлы лежат в `generated/` и коммитятся; перегенерация — вручную
скриптом `tools/generate_proto.ps1`.

**Следствия.**
+ Сборка не требует `protoc`, Python и nanopb.
+ Результат воспроизводим и одинаков у всех.
− При изменении `.proto` нужно не забыть перегенерировать (риск рассинхрона;
  митигация — раздел в документации и проверка `PB_PROTO_HEADER_VERSION`).

## ADR-013. Ориентация инструмента не управляется

**Контекст.** Для фрезеровки важна ориентация фрезы, но в первой версии её
управление не требовалось.

**Решение.** `planned.cartesian.orient`/`euler` не заполняются — робот сохраняет
ориентацию стартовой позы.

**Следствия.**
+ Проще и безопаснее на старте.
− Нельзя наклонять фрезу, обрабатывать боковые поверхности и компенсировать
  отклонения. Точка расширения: кватернион из CAM (I/J/K) или фиксированный наклон.

## ADR-014. Удалён шаблонный подпроект `VisualStudio/FrezaEgm/FrezaEgm/`

**Контекст.** Шаблон VS создал вложенный проект (`FrezaEgm.cpp` с `int main()`,
свой `CMakeLists.txt`), который не использовался и мог дать второй `main`.

**Решение.** Каталог удалён; единственная точка сборки — корневой `CMakeLists.txt`.

**Следствия.**
+ Нет путаницы с двумя `main` и двумя целями `FrezaEgm`.
− Если понадобится вернуть шаблон — он создаётся заново за 10 секунд.
