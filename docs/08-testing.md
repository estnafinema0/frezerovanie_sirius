## 1. Самотест без робота

`FrezaEgm_selftest.exe` проверяет всю цепочку, кроме живого контроллера:

```
trajectory.gcode → точки → CSV → обратное чтение → InterpolatePath
                 → protobuf-сообщение → разбор обратно
                 → UDP-обмен с «заглушкой контроллера» на 127.0.0.1:6510
```

Запуск:

```powershell
cd VisualStudio\FrezaEgm
.\build-vs\Release\FrezaEgm_selftest.exe
# или через ctest:
ctest --test-dir build-vs -C Release --output-on-failure
```

Код возврата: `0` — успех, `2` — есть проваленные проверки, `1` — не прочитался
файл траектории.

Аргументы (необязательные): `<файл-траектории> <выходной-csv>`.

## 2. Что именно проверяется

| Группа | Проверки |
|---|---|
| Разбор траектории | файл читается; 5 точек; координаты (750,0,600), (850,0,600), (850,100,600), (750,100,600), (750,0,600) |
| CSV | запись; чтение обратно; количество совпадает; координаты совпадают |
| Интерполяция | путь разбивается на сотни подточек; таблицы времени и вершин совпадают по размеру; начинается и заканчивается в стартовой точке; шаг 2 мм при 50 мм/с |
| protobuf | сообщение сериализуется (80 байт); разбирается обратно; `seqno`; `mtype = CORRECTION`; `pos` присутствует; `x = 10`; **`y = 0` и `z = 0` переданы явно**; ориентация — единичный кватернион |
| UDP | сокет-заглушка создан; клиент занял порт 6510; принял десятки `EgmRobot`; отправил десятки `EgmSensor`; первая точка 0,0,0; вторая 10,0,0 |

Всего 35 проверок; при успехе печатается «Итог: УСПЕХ».

### Регрессия (73/73 при CAM ON, 46/46 при CAM OFF)

`FrezaEgm_regression.exe` дополняет самотест и не требует робота:

* G-code/XYZ/CSV — прежние координаты и предупреждения;
* `InterpolatePath` — шаг, время, флаги вершин;
* сериализация — побайтовое сравнение с эталонами `data/cam/sensor-*.bin`;
* STL/CAM (при собранной зависимости): границы и 12 треугольников Primer1,
  ASCII = binary, отказ на испорченных файлах, лимиты, точное совпадение с
  `Primer1-base.csv`, змейка (`9` проходов при Ø4, шаг 0.7·D, покрытие обоих
  краёв, валидация разреженного и интерполированного пути, отказ точке вне змейки
  и стратегии с шагом больше диаметра).

Запуск отдельно: `.\build-vs\tests\Release\FrezaEgm_regression.exe` (в конце
печатается `73/73 checks passed; CAM=1`).
## 3. Как устроена «заглушка контроллера»

В тесте создаётся второй UDP-сокет (эмулятор робота). Он:

1. шлёт `EgmRobot` (mtype = DATA, MCI = RUNNING, моторы = ON, сходимость = да,
   обратная связь 750/0/1123) на `127.0.0.1:6510` каждые 5 мс;
2. принимает ответы `EgmSensor` и разбирает их;
3. проверяет, что приходили абсолютные позы `0,0,0` и `10,0,0`.

Так проверяется и отправка, и приём, и разбор без RobotStudio.

## 4. Проверка вручную, без робота

1. Запустить `FrezaEgm.exe` — траектория `data/trajectory.gcode` подхватится сама.
2. Нажать «Запустить траекторию» (порт 6510).
3. Ожидаемое: состояние «ожидание контроллера», через 120 с — ошибка
   «контроллер не вышел на связь». Это нормально: робота нет.
4. Нажать «Стоп» — состояние вернётся в «не запущен», порт освободится.
5. Повторить запуск — должно работать (проверка освобождения порта).

## 5. Чек-лист проверки с RobotStudio

| # | Шаг | Ожидание |
|---|---|---|
| 1 | Контроллер запущен, RAPID загружен | `ModuleEGM` виден в редакторе |
| 2 | В приложении «Запустить траекторию» | «ожидание контроллера», порт 6510 занят (`netstat`) |
| 3 | RAPID: `PP на main`, `Пуск` | робот едет в `home` = (750, 0, 600) |
| 4 | Началась сессия EGM | в приложении «отработка траектории», счётчики растут |
| 5 | Робот проходит квадрат | в журнале «точка N из 201» … «траектория завершена» |
| 6 | «Стоп» в приложении | поток прекращён, робот стоит |
| 7 | Повторный цикл RAPID | новая сессия подхватывается без перезапуска приложения |

## 6. Диагностика

| Что смотреть | Где |
|---|---|
| Сколько пакетов ушло/пришло | блок «Состояние EGM» в окне |
| Потери пакетов | `seqno` в `EgmRobot` растёт не на 1 — есть потери |
| Байты сообщения | Wireshark, `udp.port == 6510`; ожидаемая структура — `05-egm-protocol.md` |
| Занят ли порт | `netstat -ano | findstr :6510` |
| Ошибка внутри EGM-клиента | журнал в окне (строки с временем) |
| Ошибка RAPID | окно «События» контроллера, `ERR_UDPUC_COMM` |

## 7. Что не покрыто тестами

* Реальный обмен с контроллером (нужен RobotStudio).
* Поведение при потере пакетов и переполнении очереди.
* Долгая работа (часы) и утечки памяти.
* Визуальная проверка окна (только «окно создаётся и отвечает»).
* Движение робота по змейке и точность углов — проверяются вручную в RobotStudio,
  автотестами покрыт только расчёт траектории.
