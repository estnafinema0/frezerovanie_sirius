# 12. Полная инструкция: настройка RobotStudio → симуляция → управление из приложения

Пошаговый сценарий: от открытия станции до движения робота по траектории,
которую приложение FrezaEgm передаёт по EGM.

**Установлено:** RobotStudio 6.08.01 (6.08.8307.1040), RobotWare 6.08.1040.
**Порт EGM:** 6510, устройство `UCdevice`.

---

## Часть 1. Настройка RobotStudio

### 1.1. Открыть станцию

`File → Open` → `RobotStudio\FrezaEGM\FrezaEGM.rssln`.
Для `SolutionEGM_6.08.rspag` на вопрос про «перемещённую систему» ответить **No**.

### 1.2. Если кнопка `From Layout` серая

1. `File → Options → Controller` → включить **Show virtual controllers** → перезапустить RobotStudio.
2. Выделить робота `IRB1600_10_145__01` в дереве станции.
3. Сохранить станцию (`Ctrl+S`).
4. В дереве `Controllers` не должно быть контроллера (иначе `Remove System`).
5. Не открывать станцию из `Documents\RobotStudio\Solutions\SolutionEGM` — там система 6.13.

Альтернативный вход: `Controller → Virtual Controller → From Layout`.

### 1.3. Создать систему

`Home → Robot System → From Layout`:

1. **System name**: `FrezaEGM`.
2. **RobotWare**: `6.08.1040`.
3. **Options**: `616-1 PC Interface`, **`689-1 Externally Guided Motion (EGM)`**.
4. `Next → Create` (2–5 минут), затем **Start** у контроллера → состояние **Running**.

### 1.4. Проверить EGM-устройство

`Controller → Configuration → Communication` → запись **`UCdevice`**: тип `UDPUC`,
адрес `127.0.0.1`, порт **6510**. Если нет — `Add` и перезапуск контроллера.

### 1.5. Загрузить RAPID-модуль

1. Вкладка **RAPID** → панель **Modules** (или правый клик по `T_ROB1` → `Add Module…`).
2. `Add Module…` → `File…` → `RobotStudio\ModuleEGM.mod` → `OK`.
3. В дереве `T_ROB1 → Modules` появится `ModuleEGM`, внутри — `PROC main()`.

## Часть 2. Подробно: от загрузки модуля до движения

### 2.1. Проверить, что модуль загрузился правильно

Чек-лист (всё видно в редакторе RAPID):

* в `T_ROB1 → Modules` есть **`ModuleEGM`**;
* внутри видны `PROC main()`, `home`, `egm_id`, `egm_condition`, `corr_frame`;
* **нет красных подчёркиваний**. Если `EGMSetupUC` / `EGMActPose` / `EGMRunPose`
  подчёркнуты — в системе не включена опция EGM (см. §2.7).

Если модуля нет: правый клик по `T_ROB1` → `Add Module…` → `File…` → выбрать
`ModuleEGM.mod`.

### 2.2. Поставить указатель программы на `main`

Кнопка **`PP to Main`** (вкладка RAPID или `Debug → PP to Main`).

Признак успеха: в редакторе у строки `PROC main()` появилась жёлтая стрелка
(указатель программы), а в строке состояния показано `main`.

Зачем: `Start` запускает выполнение **с указателя программы**, а не «с начала файла».

### 2.3. Сначала запустить приложение

1. Запустить `VisualStudio\FrezaEgm\build-vs\Release\FrezaEgm.exe`.
2. Убедиться: «точек: 5», поля `Порт = 6510`, `период = 4`, `шаг = 2`, `скорость = 50`.
3. Нажать **«Запустить траекторию»**.
   * журнал: «запущено (траектория): точек 4»;
   * панель состояния: **«ожидание контроллера»**;
   * порт занят: `netstat -ano | findstr :6510` показывает `UDP 0.0.0.0:6510`.

Почему так: EGM-клиент отвечает на адрес того, кто прислал пакет. Пока контроллер
не прислал ни одного пакета, отправлять некуда — приложение только слушает порт.

### 2.4. Нажать Start в RobotStudio

Кнопка **`Start`** (зелёный треугольник) на вкладке RAPID или на панели контроллера.

Что произойдёт по шагам:

1. Включаются моторы (в симуляции автоматически).
2. Робот едет в `home` = (750, 0, 600) — это `MoveJ home, v100, fine, toolPencil`.
3. Вызывается `EGMSetupUC … "UCdevice" \Pose` — контроллер открывает EGM-сессию
   и начинает отправлять `EgmRobot` на `127.0.0.1:6510`.
4. Вызывается `EGMRunPose` — контроллер ждёт от нас `EgmSensor`.

В приложении в течение 0,1–0,5 с:

* журнал: **«контроллер найден, начинаем поток EGM-сообщений»**;
* состояние: **«отработка траектории»**;
* «Принято от робота» и «Отправлено пакетов» начинают расти (~250 в секунду).

Если через 2–3 секунды состояние всё ещё «ожидание контроллера»:

| Причина | Проверка |
|---|---|
| В RAPID не нажат `Start` | нажать, проверить, что робот поехал в `home` |
| Опция EGM не включена | `ModuleEGM` не компилируется, `EGMSetupUC` подчёркнут |
| Другой порт | `SIO.cfg` → у `UCdevice` должен быть 6510 |
| Порт занят не приложением | `netstat -ano | findstr :6510` покажет чужой PID |

### 2.5. Что происходит во время движения (таймлайн)

| Время | Приложение | Робот |
|---|---|---|
| 0 с | «отработка траектории», цель (750, 0, 600) | стоит в home |
| ~2 с | цель (850, 0, 600) | едет +100 мм по X |
| ~4 с | цель (850, 100, 600) | едет +100 мм по Y |
| ~6 с | цель (750, 100, 600) | едет −100 мм по X |
| ~8 с | цель (750, 0, 600) | возвращается в начало |
| конец | «траектория завершена», затем «сессия EGM закрыта» | стоит в home |

С включённой интерполяцией (галочка в блоке «EGM-соединение», по умолчанию включена)
путь разбивается на подточки по 2 мм; время на подточку = шаг / скорость
(2 мм / 50 мм/с = 40 мс), всего ~201 подточка. На прямых цель движется непрерывно,
на вершинах — короткая досылка, чтобы угол не срезался. Без интерполяции робот
перемещается сразу по 5 вершинам.

На что смотреть в панели «Состояние EGM»:

| Поле | Смысл |
|---|---|
| Точка: N / 4 | какая точка удерживается сейчас |
| Цель (TCP, мм) | абсолютная поза, отправленная в `planned.cartesian.pos` |
| Факт. поза (мм) | что контроллер прислал в `EgmRobot.feedBack` (абсолютные координаты базы) |
| Отправлено пакетов | ≈250 в секунду при периоде 4 мс |
| Принято от робота | должно быть примерно столько же; сильно меньше — потери |
| MCI | «работает» = сессия EGM активна |
| Моторы | «включены» |
| Сходимость | «да» — робот в пределах `egm_condition` (±1 мм) |

### 2.6. Ручные команды

Смещения задаются в мм **от первой точки загруженной траектории** (она же `home`);
приложение отправляет уже абсолютную позу `base + d`.

| Действие | Что будет |
|---|---|
| `dX = 50`, «Отправить точку» | робот сместится на 50 мм по +X от первой точки и останется |
| `Home (0, 0, 0)` | вернётся в первую точку = home |
| `dZ = -100`, «Отправить точку» | опустится на 100 мм |

Каждая ручная команда заново запускает поток (предыдущий останавливается),
порт при этом не освобождается.

### 2.7. Если опции EGM нет в системе

Признак: `EGMSetupUC` подчёркнут, модуль не компилируется.

В RobotWare 6.08 опция EGM — это только конфигурация, поэтому её можно добавить
в уже созданную систему: `SIO.cfg` (`UCdevice`, 6540→6510), `MOC.cfg`
(`EXT_MOTION_DATA "default"`), `MMC.cfg` (процедуры из `rlegm.cfg`).
Сообщите мне — подготовлю скрипт под вашу систему.

### 2.8. Завершение и повторный запуск

1. После последней точки — «удержание последней точки»: робот стоит, поток идёт.
2. **«Стоп»** в приложении → поток прекращён, порт освобождён.
3. Контроллер через ~0,25 с теряет сенсор → `ERR_UDPUC_COMM` → ветка `ERROR`
   в модуле (`TRYNEXT`) → `EGMRunPose` вызывается снова и снова ждёт сенсор.
   В журнале событий RobotStudio это видно как повторяющееся
   «EGM: no data from sensor». Это нормально.
4. Повтор: нажать «Запустить траекторию» — RAPID уже ждёт, сессия подхватится сама.
   Если нажимали `Stop` в RAPID — нажать `PP to Main` и `Start`.

## Часть 3. Управление из приложения

| Элемент | Назначение |
|---|---|
| «Открыть файл…» | загрузить G-code (G0/G1, G90/G91, G20/G21) или `x y z` |
| «Сохранить CSV…» / «Загрузить CSV…» | точки в `index,x,y,z` и обратно |
| «Порт» | UDP-порт EGM (6510) |
| «Интерполировать», «шаг, мм», «скорость, мм/с» | разбиение пути на мелкие шаги (2 мм, 50 мм/с) |
| «период, мс» | период отправки `EgmSensor` (4 мс = 250 Гц) |
| «Запустить траекторию» | старт потока: занимает порт и ждёт контроллер |
| «Стоп» | остановка потока и освобождение порта |
| dX / dY / dZ + «Отправить точку» | смещение от первой точки, мм |
| `Home (0, 0, 0)` | возврат в первую точку (home) |
| «Журнал» | события с отметкой времени |
| «Состояние EGM» | точка, цель, факт. поза, счётчики, MCI, моторы, сходимость |

**Своя траектория:** первая точка файла должна совпадать с `home`
(750, 0, 600), потому что передаются абсолютные координаты TCP. Дуги `G2/G3` огрубляются до
отрезков, ориентация инструмента не управляется, интерполяции нет.

## Часть 4. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «From Layout» серая | скрыты вирт. контроллеры / робот не выделен / станция не сохранена / контроллер уже есть | §1.2 |
| `ERR_UDPUC_COMM` в RAPID | приложение не запущено, не тот порт, нет опции EGM | запускать приложение первым |
| «не удалось занять UDP-порт» | второй экземпляр приложения | закрыть лишний |
| Робот стоит, пакеты идут | `egm_condition`, `MaxSpeedDeviation`, `PosCorrGain` | смотреть «Цель» и «Сходимость» |
| Робот едет не туда | `home` ≠ первой точке файла | согласовать `home` и файл |
| «нет пакетов от контроллера более 2 с» | сессия EGM закрыта в RAPID | `Start` в RAPID |
| Модуль не компилируется | нет опции EGM | §2.7 |

## Часть 5. Ограничения

* Только виртуальный контроллер; на реальном роботе EGM требует оценки рисков.
* Ориентация инструмента не передаётся (фреза сохраняет ориентацию `home`).
* Нет интерполяции и управления подачей — движение «точка за точкой» с паузами.
* RobotStudio 6.08 не сертифицирован под Windows 11.
