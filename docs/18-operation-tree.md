# Дерево операций CAM (офлайн)

Новый режим добавлен отдельно от автоматической программы и расчёта одной грани.
Рабочий обмен FrezaEgm / ABB не менялся. Новая программа содержит XYZ + quaternion
в системе детали; её CSV нельзя загружать в прежний XYZ-путь FrezaEgm.

## Запуск на Windows

PowerShell, установлен Visual Studio 2022 с Desktop development with C++, CMake и Git:

```powershell
git clone https://github.com/estnafinema0/frezerovanie_sirius.git
cd frezerovanie_sirius
git fetch origin
git switch feature/cam-operation-tree
git pull --ff-only origin feature/cam-operation-tree
cmake -P MillingAnalyzer/cmake/Dependencies.cmake
cmake -S MillingAnalyzer -B build-bezier-viewer -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$pwd/build-bezier-viewer-deps/occt" -DEIGEN_INCLUDE_DIR="$pwd/build-bezier-viewer-deps/eigen"
cmake --build build-bezier-viewer --config Release --parallel 4
ctest --test-dir build-bezier-viewer -C Release --output-on-failure
.\build-bezier-viewer\Release\MillingAnalyzer.exe --serve
```

Если репозиторий уже есть, начать с `cd` в его каталог и `git fetch`.
Не переключать ветку поверх несохранённых изменений. Все DLL из папки Release
должны лежать рядом с EXE. Не переносить один EXE отдельно. Окно программы
оставить открытым; браузер открывает напечатанный локальный адрес. Порт и адрес
меняются при каждом запуске. Другому человеку нужно запустить EXE на его компьютере,
а не открывать чужую ссылку `127.0.0.1`.

STEP может лежать в любой доступной папке: «Открыть STEP / STP…» или перетаскивание.
Копировать его в исходники не требуется. Контрольные публичные модели:
`MillingAnalyzer/data/automatic-box.step`, `stepped-solid.step`, `blind-hole.step`.
Частные модели детали и шпинделя в репозиторий не включены.
Для воспроизводимого примера внешней спирали:

```powershell
.\build-bezier-viewer\Release\milling_operation_tests.exe --example build-bezier-viewer/operation-demo
```

В `operation-demo` появятся `terraced-part.step`, `external-helix.json` и
`external-helix.poses.csv`. Деталь 20×20×4 мм с выступом 10×10×2 мм; блок
[-2,-2,0]…[22,22,6], фреза Ø2,5 мм, длина 20 мм, припуск 0,1 мм,
шаг спирали 1 мм. В UI выбрать всю деталь, внешний контур, верх 6 и основание 0.
Эти файлы также входят в Windows-артефакт CI.

## Порядок работы

1. Загрузить STEP. Проверить единицы и габариты.
2. Ввести шесть границ фактической заготовки. «Пример блока по габаритам» —
   только удобный офлайн-пример. Задать фрезу, шаги, подачу и допустимость осевого врезания.
3. «Предложить операции» создаёт **черновики**, не запускает обработку.
   Можно выбрать грань в 3D-виде и нажать «Добавить». Затем выбрать
   «Черновая выбранной грани» или «Чистовая выбранной грани».
4. Для каждой операции выбрать геометрию в её списке. Можно нажать грань на
   3D-модели и затем «Взять грань из 3D-вида». Для обхода всей детали выбрать
   «Вся деталь · внешний контур / объём» и способ «Внешний контур».
   Это силуэт всей детали, включая нижние уступы и вогнутости, а не bounding box.
   Выбор конкретной горизонтальной грани ограничивает контур её внешней границей.
5. Указать высоты, слой/шаг спирали и припуск; нажать «Подтвердить операцию».
   «Черновая · весь объём» использует весь блок; черновая грани ограничена
   её проекцией, а чистовая по нормалям — выбранной поверхностью.
   У контура низ фиксирован на Z min заготовки: при Z min=0 спираль доходит до нуля.
   Выбор верхней грани больше не подменяет низ её высотой. Шаг спирали — снижение
   за полный оборот; последний виток может быть мельче, затем полный обход дна.
6. Стрелками ↑/↓ задать порядок. Он сохраняется при расчёте; скрытой перестановки
   «сначала всё черновое» нет. Изменение инструмента или блока снимает подтверждения.
7. «Рассчитать дерево операций». Статус рядом с кнопкой объясняет недостающие
   данные и номер неудачной операции. При ошибке предыдущий результат сохраняется.
8. В просмотре выбрать всю программу или отдельную операцию, включить воспроизведение,
   посмотреть остаток материала и пересечения. Выгрузить «Позы CSV» / «Данные JSON».
   JSON содержит подтверждённые параметры операций. Обновление страницы восстанавливает
   последнее рассчитанное дерево текущего локального сервера. Новый STEP сбрасывает дерево.
9. «Сбросить траекторию» удаляет рассчитанные движения и остаток, останавливает
   воспроизведение и отключает CSV. Модель, настройки и дерево в текущей вкладке
   остаются; можно пересчитать. После перезагрузки страницы очищенный сервер
   отдаёт модель без программы (неподсчитанные черновики дерева не сохраняются).

## Обработка по выбранной грани

Все импортированные CAD-грани доступны в списке независимо от типа поверхности.
«Черновая выбранной грани» строит локальную систему по средней нормали,
защищает всю модель и выбирает слои только внутри проекции выбранной грани
с заданным припуском. Для вертикального внутреннего цилиндра выбирается
стратегия отверстия. «Чистовая выбранной грани» выбирает плоское выравнивание,
отверстие или адаптивные проходы по реальной поверхности и её нормалям.
Наклонная / кривая чистовая требует предшествующую черновую этой грани
либо всего объёма. Проверены плоская, наклонная, Безье и цилиндрическая внутренняя грани.

Выбор любого CAD-типа не означает доступность любой геометрии одной установкой:
нижние грани, полный наружный цилиндр с взаимно противоположными нормалями,
поднутрения и поверхности, которым нужна разбивка на локальные участки, могут
быть отклонены с объяснением. Для локальной черновой повёрнутый блок также
должен укладываться в предел 30 мм по глубине и подтверждённую длину фрезы.
Чистовая использует CAD-поверхность, а не аппроксимацию прямоугольником.

## Реализованные стратегии и границы

| Операция | Геометрия и алгоритм |
|---|---|
| Черновая | Весь замкнутый объём. Прежний алгоритм нисходящих Z-слоёв, верхняя огибающая детали, припуск и проверка вовлечения материала. |
| Выравнивание | Выбранная горизонтальная грань с нормалью +Z. Послойные параллельные проходы внутри её trim-границы. Низ = Z грани + припуск. |
| Карман | Выбранное горизонтальное дно. Послойные проходы с учётом радиуса, островов и границ дна; вертикальные входы, проверяемые по всей детали. Неплоское дно этим типом не поддерживается. |
| Отверстие | Полная внутренняя цилиндрическая стенка с осью параллельно Z. Врезание в центр, последовательная выборка сердцевины и концентрических колец по слоям. Поддержаны сквозные и глухие отверстия. Высоты ограничены стенкой; радиальный запас проверки сетки 0,03 мм добавляется к заданному припуску. Выступы и наклонные оси отклоняются. |
| По нормалям | Реальная B-rep поверхность, адаптивные проходы и нормали, параллельный перенос ориентации без добавленного вращения вокруг оси фрезы. Нужна предшествующая черновая и нулевой припуск. Нижние поверхности и грани с несовместимыми нормалями требуют другой установки/разбиения. |
| Внешний контур | Весь силуэт детали (объединение XY-проекций верхних треугольников OCCT) либо внешняя граница горизонтальной грани. OCCT `BRepOffsetAPI_MakeOffset`: смещение наружу на радиус + припуск + запас 0,03 мм для силуэта / 0,01 мм для точной границы грани. Ось инструмента неизменно +Z детали, ориентация постоянна во время резания (единичный quaternion при самостоятельном запуске контура). Низ — Z min заготовки. Слои либо спираль с заданным по Z шагом за полный обход и заключительным полным обходом дна. Разветвляющиеся смещения отклоняются. Внутренний произвольный контур этим типом пока не поддерживается. |

Расчёт не объявляет, что весь лишний материал снят: показывает остаток.
Стратегия кармана выполняет выборку плоского дна, а не отдельный точный проход
по всем стенкам кармана. Узкие места и поднутрения могут остаться необработанными.
Результат с красными пересечениями предназначен для диагностики и требует изменения
порядка, геометрии, инструмента или установки. Это не промышленный постпроцессор.

Заготовка одна, инструмент один на дерево, максимум 32 операции / 100000 поз.
Силуэт целой детали ограничен 2000 проецируемых треугольников и одним внешним
контуром; несколько раздельных силуэтов отклоняются. Запас 0,03 мм учитывает
аппроксимацию сетки 0,02 мм; итоговые отрезки дополнительно проверяются по модели.
Лимиты прежнего прототипа заготовки сохраняются: размер до 200 мм, высота до 30 мм
и не больше длины фрезы. Координаты — абсолютные в системе детали, без калибровки базы ABB.

## Расчёт и проверки

`src/operation_plan.cpp` — отдельный модуль. `/operations` принимает подтверждённый
список и проверяет версию загруженной модели, чтобы дерево из другой вкладки не
применилось к заменённой детали. Старые `/calculate`, `/program`, `/auto-program`
и `program.cpp` сохранены. `/reset-trajectory` проверяет версию модели и очищает
результат атомарно. Только общий сервер/просмотр расширены новыми маршрутами.

Каждая операция создаёт подводы и отводы; между операциями ориентация переводится
через +Z над блоком. Полная составная траектория, включая переходы и SLERP,
проверяется по сетке CAD и по остаточному материалу из исходного блока в порядке
операций. Проверка дискретная: не включает держатель, крепления, IK робота,
прогиб, усилия и физическую пригодность режимов резания.

OCCT остаётся 7.9.3, commit `a016080bf6738d6aeae020badee4e888ad1540a5`;
Eigen остаётся 3.4.0. Для смещений добавлен TKOffset, обновлены маркер установки и
ключ Windows CI-кэша; старую неполную установку не принимаем за готовую.

Новый тест `milling_operations` проверяет порядок, подтверждение, NaN, неверную грань,
карман, сквозное/глухое отверстие, отказ обработки выступа как отверстия, слои и
спираль контура, ступени и вогнутый силуэт, радиальную компенсацию и неизменный
quaternion, низ заготовки, черновую/чистовую выбранных плоской, наклонной и Безье-граней.
HTTP-тест проверяет сброс, повторный расчёт, маршрут, устаревшее дерево,
ошибку второй операции и сохранение последнего результата. Старые наборы геометрии,
автоматической программы и защищённого ABB продолжают выполняться.

## Принцип интерфейса

Использована схема стандартного CAM: инструмент → геометрия → высоты/проходы →
подтверждение операции → расчёт. Первичные примеры Autodesk:
[2D Contour](https://help.autodesk.com/view/fusion360/ENU/?contextId=2D-CONTOUR-STEPS),
[Bore](https://help.autodesk.com/cloudhelp/ENU/Fusion-CAM/files/2D-BORE-STEPS.htm).
Это аналогия организации работы, а не заявление о равенстве реализованных стратегий Fusion.
