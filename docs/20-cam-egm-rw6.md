# CAM → EGM Pose: единый комплект для RobotStudio / RobotWare 6

Ветка `feature/cam-egm-ui-rw6`. Контрольная платформа — **отдельный Windows-ПК, RobotStudio, виртуальный IRC5 / IRB1600-10/1.45, RobotWare 6**, как указал владелец проекта. Точную версию RW6 и состав опций проверяет оператор в своей виртуальной станции.

`MillingAnalyzer.exe` объединяет загрузку STEP, расчёт, просмотр, проверку поз и отправитель EGM. Отдельный процесс или перенос CSV между программами больше не требуются. Браузер обращается только к локальному C++ приложению; именно C++, а не браузер, открывает UDP.

**Физический контроллер не использовался.** Этот профиль предназначен для опыта в копии виртуальной станции с демонстрационным карандашом. Флажок «виртуальный контроллер» — подтверждение оператора: по UDP невозможно надёжно отличить VC от физического контроллера. Установленные параметры шпинделя, измеренный TCP, привязка детали, достижимость и коллизии всего робота здесь не подтверждены.

## 1. Запуск готовой сборки на Windows

1. В GitHub Actions откройте успешный запуск ветки `feature/cam-egm-ui-rw6`, скачайте артефакт **MillingAnalyzer-RW6-EGM-Windows-x64**.
2. Распакуйте **весь** архив, например в `C:\SiriusCAM`. Рядом с `MillingAnalyzer.exe` должны остаться DLL, `licenses`, `Start-Milling.cmd`, `MillingPose6510.mod`, этот README и папка `examples`. Не запускайте EXE внутри ZIP.
3. Запустите `Start-Milling.cmd` двойным щелчком. Либо в PowerShell:

```powershell
Set-Location C:\SiriusCAM
.\MillingAnalyzer.exe --serve
```

4. Откроется браузер с локальным адресом из окна программы. Адрес и порт веб-интерфейса выбираются при каждом запуске; это **не UDP-порт EGM 6510**. Окно программы должно оставаться открытым.
5. STEP можно хранить в любом месте, включая пути с пробелами и кириллицей. Нажмите «Открыть STEP / STP…» или перетащите файл в область загрузки. Переносить его рядом с EXE не нужно. Для первого опыта используйте `examples\automatic-box.step`. В `examples` также лежат `flat.step`, рассчитанный приложением `flat.poses.csv`, параметры `flat-parameters.json` и `rough-program.poses.csv` с осевым врезанием. Они получены сквозным тестом; CSV — для сравнения/проверки, в интерфейс загружается STEP.

Если Windows сообщает об отсутствующем MSVC runtime, установите официальный Microsoft Visual C++ Redistributable x64 для Visual Studio 2022. Если отсутствует DLL OCCT, распакуйте весь комплект заново; не подменяйте её случайной версией.

## 2. Если нужна сборка из Git

Требуются Git, Visual Studio 2022 с Desktop development with C++ и Windows SDK, CMake, Python 3 в PATH. Выполняйте из PowerShell. Для новой копии:

```powershell
git clone --branch feature/cam-egm-ui-rw6 https://github.com/estnafinema0/frezerovanie_sirius.git
Set-Location frezerovanie_sirius
```

Для существующей чистой копии (сначала сохраните свои незакоммиченные изменения):

```powershell
git status --short
git fetch origin
git switch feature/cam-egm-ui-rw6
git pull --ff-only origin feature/cam-egm-ui-rw6
```

Из корня репозитория:

```powershell
cmake -P MillingAnalyzer/cmake/Dependencies.cmake
cmake -S MillingAnalyzer -B build-bezier-viewer -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$pwd/build-bezier-viewer-deps/occt" -DEIGEN_INCLUDE_DIR="$pwd/build-bezier-viewer-deps/eigen"
cmake --build build-bezier-viewer --config Release --parallel 4
ctest --test-dir build-bezier-viewer -C Release --output-on-failure
powershell -NoProfile -ExecutionPolicy Bypass -File MillingAnalyzer/tools/package-rw6.ps1
.\build-bezier-viewer\RobotStudio-RW6\Start-Milling.cmd
```

Команды запускайте по очереди; при ненулевом коде завершения сборки или тестов сначала устраните ошибку. OCCT 7.9.3 и Eigen 3.4.0 закреплены существующим скриптом зависимостей. Для EGM используются существующие nanopb и `egm3.pb.c/.h` без изменений. OpenCAMLib не требуется новому STEP/Безье-планировщику; старый FrezaEgm продолжает собираться отдельно с CAM ON и OFF.

## 3. Расчёт и подготовка

Для небольшого первого опыта: загрузите `automatic-box.step` (20×10×5 мм), выберите верхнюю грань Z=5 в 3D-виде. Фреза Ø2.5, длина 8 мм, шаг проходов 2 мм, шаг точек 1 мм, подача 10 мм/с, зазор 2 мм. В «Прежние способы расчёта» выберите «Вручную · чистовая одной грани» и нажмите «Рассчитать выбранный режим». Просмотрите **всю грань**, включая подвод и отвод. Это удобный короткий тест передачи, не технологический режим резания.

Для программы с несколькими операциями остаётся прежний порядок: явная заготовка → дерево операций → подтверждение геометрии каждой операции → расчёт дерева. В списке просмотра выберите **«0 · Программа»**. При выборе отдельной грани будет подготовлена только её цельная траектория, а не всё дерево. Выбор отдельного прохода в просмотре не обрезает отправляемую цельную траекторию.

В разделе **«5. Проверка в RobotStudio · RW6»**:

1. Для просмотра разных заготовок на одном ПК включите **«Выгрузка для локальной RobotStudio»** перед подготовкой. В этом режиме отметки о пересечении и остаточном материале допускаются при выгрузке и сохраняются в данных планировщика. Подготовленная таким образом траектория доступна для передачи только в виртуальном профиле при Bind IP и Peer IP 127.0.0.1. Нажмите **«Проверить и подготовить выбранную траекторию»**. Движение не запускается и UDP-порт ещё не открыт.
2. Программа проверит непрерывный путь, реальные флаги столкновений, числа, время, скорости, кватернионы, весь CSV и кодирование команд. Появятся число исходных поз, длительность, границы в системе детали и `runSeconds` для RAPID.
3. При необходимости нажмите **«Скачать подготовленные позы CSV»**. Это тот же зафиксированный результат, который будет передан. Форматы CSV из handoff сохранены. Встроенный адаптер поддерживает `motion=4` — осевое врезание; старый `MillingVirtualEgm` из ZIP его по-прежнему отклоняет. Не переименовывайте врезание в другой тип ради обхода проверки.
4. Для проверки изменения ориентации используйте встроенный выпуклый пример «Безье», те же параметры и подачу 10 мм/с. Ориентация остаётся постоянной на прямом подводе и меняется после выхода на поверхность. Дополнительное вращение фрезы вокруг её собственной оси не добавляется.

При обычной подготовке пересечения по-прежнему блокируют выгрузку. Успешный новый расчёт, загрузка и сброс аннулируют старую подготовку. Ошибка расчёта сохраняет предыдущий результат. Во время активного EGM изменение источника блокируется и в интерфейсе, и на сервере.

## 4. Подготовка RobotStudio

Делайте это **в отдельной копии станции с виртуальным контроллером**, не заменяя рабочий `RobotStudio/ModuleEGM.mod` или конфигурацию физического робота.

1. Проверьте механизм **IRB1600-10/1.45**, RobotWare **6**, опции **689-1 Externally Guided Motion** и **UDPUC Driver**. В исходной станции указан RW6.08; прикладное руководство RW8 из вложения не заменяет документацию этой установки.
2. В Controller → Configuration → Communication → Transmission Protocol создайте/проверьте `UCdevice`, тип `UDPUC`. Remote Address — адрес **компьютера, где работает MillingAnalyzer**; Remote Port Number — `6510`. В Motion → External Motion Interface Data должна существовать конфигурация `default`. После изменения конфигурации перезапустите VC.
3. Если обе программы на одном Windows-ПК, везде используйте **127.0.0.1**, порт **6510**. Если CAM и VC на разных ПК в тестовой сети: в CAM задайте локальный IPv4 его Ethernet-интерфейса, ожидаемый IPv4 ПК с VC и локальный порт; в UCdevice — тот же адрес CAM и порт. Разрешите входящий UDP только для выбранного профиля/адреса VC в Windows Firewall. Не используйте адрес физического контроллера в этом опыте.
4. В копии T_ROB1 выгрузите прежний программный модуль с `main`, загрузите **`MillingPose6510.mod`** из комплекта. Выполните **Check Program**. Это обязательная проверка синтаксиса и опций именно вашей версии RW6.
5. В Program Data установите `virtualConfirmed := TRUE` и `runSeconds` **точно из подготовленной траектории**. Значение равно `ceil(duration)+3`, диапазон 3…243 с. `CondTime=300` в модуле не является длительностью обработки: сессию явно завершает таймер и EGMStop.
6. Установите виртуальный робот в выбранную исходную позу до запуска. Модуль считывает текущие суставы через `CJointT()` и задаёт `MoveAbsJ` в эти же суставы с зоной `fine`, требуемой для EGMRunPose. Заданной точки Home в этом модуле нет. Используется демонстрационный `simTool` с TCP `[0,0,280]`. Настройте Collision Set и проверьте свободное пространство по всей траектории.
7. Используйте масштаб моделирования **1×**, Motors On, PP to Main и один цикл. CAM ждёт первый валидный пакет 30 с. Первый feedback задаёт и положение, и ориентацию всей траектории, поэтому при смене позы старта проверяйте новое размещение относительно детали и оснастки.

## 5. Запуск и критерии проверки

1. В CAM подтвердите флажками виртуальную станцию и демонстрационное совмещение первой позы с первым откликом VC.
2. Нажмите **«Начать ожидание EGM»**. Дождитесь состояния ожидания. CAM только слушает выбранный порт.
3. Запустите **T_ROB1** в RobotStudio. Контроллер первым отправит `EgmRobot`; CAM ответит `EgmSensor` на фактический IP и исходный UDP-порт этого пакета. Новый отправитель с другого IP/порта и повторные/старые номера пакетов игнорируются.
4. Первая команда совпадает с измеренной первой позой TCP. Далее показываются счётчик пакетов, время, демонстрационное преобразование и консервативные границы в базе.
5. Проверяйте след TCP **и ориентацию** на подходе, рабочих проходах, переходах и отводе. Для совмещения CAD со следом поместите модель в RobotStudio по выведенному переносу и повороту. Преобразование получается из первого отклика, поэтому до старта его численные значения ещё неизвестны. Это не размещение для реальной обработки.
6. В конце CAM удерживает последнюю цель. Для состояния «Завершено» нужны ошибка конечного TCP ≤0.1 мм, угол ≤0.5° непрерывно 0.2 с и затем прекращение обратной связи. Дополнительно проверьте штатный выход T_ROB1 через **EGMStop → EGMWaitCond → EGMReset** и отсутствие ошибок Event Log. Прекращение UDP само по себе не доказывает нормальное завершение RAPID.
7. «Удержать / отменить» до первого пакета отменяет ожидание. Во время обмена фиксирует измеренную позу TCP и отвечает ею до остановки EGM в RAPID. Это **не аварийный останов**. Для завершения нажмите Stop в RobotStudio или дождитесь таймера RAPID. Закрывайте приложение после остановки VC.

При потере feedback ≥0.5 с до достигнутого конца — ошибка, а не успех. При возобновлении feedback после промежутка ≥100 мс движение не перескакивает вперёд по времени: новый адаптер прерывает воспроизведение. Это отдельные правила нового адаптера; таймеры старого FrezaEgm не менялись. После паузы/ошибки начните новый опыт, не пытайтесь продолжить с середины.

Сохраните для отчёта точную версию RW6, результат Check Program, исходный STEP, подготовленный CSV, параметры инструмента, перенос и поворот, снимок следа TCP, конечную позу, Event Log и результат остановки. На этой машине RobotStudio отсутствует: перечисленные действия должен выполнить оператор Windows-ПК.

## 6. Как соединены модули

```text
STEP → OCCT / Безье / дерево операций → проверенные Pose и временной профиль
     → CSV в памяти (тот же CSV доступен для скачивания)
     → preflight: все сегменты, лимиты, кодирование/декодирование с шагом 4 мс
     → неизменяемый Plan → явный Start → отдельный поток EGM
     → linear XYZ + SLERP → привязка → nanopb EgmSensor → UDP → виртуальный IRC5
```

Точка подключения — `MillingAnalyzer/src/server.cpp`: сервер хранит результат расчёта, а не доверяет присланному браузером массиву координат или «обнулённым» флагам столкновений. `/egm/prepare`, `/egm/start`, `/egm/stop`, `/egm/status`, `/egm/download` используют тот же закрытый локальный адрес и проверку Origin. Время расчёта/проверки не входит в сетевую сессию. `egm_session.cpp` не вызывает CAM, CAD, чтение STEP/CSV с диска или тяжёлые геометрические проверки в потоке UDP.

В виртуальном профиле оси TCP повернуты относительно прежнего simTool на 180° вокруг локальной X: +Z направлена в противоположную сторону, точка TCP сохранена. Обновите одновременно приложение и RAPID-модуль. В формулах виртуального профиля `C=I`, первая поза планировщика `(p0,q0)`, первый feedback `(pf,qf)`:

```text
R = qf × C⁻¹ × q0⁻¹
T = pf − R·p0
p_base_TCP(t) = R·p_part_cutter(t) + T
q_base_TCP(t) = R × q_part_cutter(t) × C
```

Кватернионы идут `w,x,y,z`; преобразование осей задаётся рамкой simTool. TCP 280 мм, масса, центр тяжести и длина фрезы не прибавляются к XYZ. В nanopb сохраняются explicit presence нулевых XYZ, seqno/tm и всех четырёх компонент ориентации; Euler не посылается. Отправляется абсолютная поза в базе, как настроено в отдельном RAPID-модуле. Один валидный feedback вызывает один ответ. Запрошенные `SampleRate=4` и проверка на сетке 4 мс не являются измерением реального периода.

Ограничения подготовки: до 64 MiB, 200000 поз, 240 с, шаг времени `(0,10]` с, расстояние между узлами ≤10 мм, угол ≤0.53 рад, скорость ≤50.001 мм/с и ≤0.524 рад/с. Строка CSV ограничена 8 KiB. NaN/Inf, неединичные кватернионы/нормали, несогласованные индексы, обнаруженные столкновения отклоняются с номером точки. Более длинная программа не разрезается автоматически: повторное совмещение с feedback изменило бы размещение.

Проверки CAM учитывают цилиндр фрезы и дискретные промежуточные позы, но не являются доказательством отсутствия столкновений всего непрерывного движения, не включают держатель и кинематику робота. Сериализация не заменяет проверку механики в RobotStudio. Профиль не рассчитан на производственное резание.

## 8. Регрессия

Исходный результат до интеграции: 5/5 CTest MillingAnalyzer на macOS. Новые проверки: 36 условий preflight/Protobuf и сквозной HTTP/UDP тест с синтетическим STEP, чистовой плоскостью, черновым `motion=4` и меняющейся ориентацией Безье. Он проверяет источник пакетов, дубликаты, первый/последний TCP, busy-порт, остановку, потерю feedback, устаревшие задания и запрет смены источника при активном обмене. Отдельный комплект ZIP сохраняет свои 4 теста.

Защищённый тест сравнивает с `2f259357c2a276c98c353471207110a2ddcae1fb`: EgmClient `.cpp/.h`, схему/options/generated nanopb, сам nanopb, `RobotStudio` целиком, старые парсеры/интерполяцию/selftest и исходные данные. Их поведение и исходники не изменены. Итоговые числа CI и ссылка на прогон приводятся в PR; это офлайн-проверки и UDP-loopback, не результат испытания ABB.
