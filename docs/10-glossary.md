# 10. Глоссарий

| Термин | Что это |
|---|---|
| **STL** | Формат 3D-модели: набор треугольников (поверхность). Траектории движения инструмента не содержит. |
| **CAM** | Computer-Aided Manufacturing — программа, которая по модели и инструменту строит траекторию обработки и выгружает её в G-code. |
| **G-code** | Текстовый язык УП (ISO 6983): команды `G0/G1` (перемещение), координаты `X/Y/Z`, подача `F`. |
| **Постпроцессор** | Модуль CAM, который переводит внутреннюю траекторию в G-code конкретного станка/стойки. |
| **УП** | Управляющая программа — файл с G-code. |
| **EGM** | Externally Guided Motion, опция RobotWare `689-1`: внешнее управление движением робота по UDP с высокой частотой. |
| **Pose guidance** | Режим EGM, где сенсор задаёт **абсолютную позу TCP** в системе коррекции (`EGMActPose` + `EGMRunPose`). |
| **Joint guidance** | Режим EGM, где сенсор задаёт углы шарниров (`EGMActJoint` + `EGMRunJoint`). |
| **Сенсор (в EGM)** | Наша программа: сторона, которая шлёт `EgmSensor` и получает `EgmRobot`. |
| **`EgmSensor`** | Сообщение ПК → контроллер с коррекцией (`planned`, `speedRef`). |
| **`EgmRobot`** | Сообщение контроллер → ПК с телеметрией (`feedBack`, `mciState`, `motorState`, …). |
| **`seqno`** | Порядковый номер сообщения — по нему видно потери пакетов. |
| **MCI** | Motion Control Interface — подсистема RobotWare, реализующая EGM; её состояние приходит в `mciState`. |
| **Convergence** | Признак того, что робот дошёл до заданной точки в пределах допуска (`egm_condition`). |
| **`egm_condition`** | Допуск сходимости в RAPID (`egm_minmax`, например `[-1, 1]` мм/град). |
| **`corr_frame`** | Система координат коррекции в `EGMActPose`; в примере — единичная, `EGM_FRAME_BASE`. |
| **`base` (система базы)** | Система координат робота; координаты в G-code проекта трактуются как координаты базы. |
| **`tool0` / `wobj0`** | Стандартные инструмент и объект работы в RAPID. |
| **`toolPencil`** | `tooldata` карандаша: TCP на кончике, 280 мм по Z от фланца. |
| **Интерполяция** | Разбиение отрезков траектории на мелкие подточки, чтобы робот шёл по прямой, а не прыгал по вершинам. |
| **STL** | Формат сетки из треугольников; хранит только геометрию, траектории внутри нет. |
| **OpenCAMLib (OCL)** | C++-библиотека расчёта траекторий; здесь `CylCutter` + `PathDropCutter` по верхней грани STL. |
| **CAM** | Расчёт траектории по модели; в проекте — встроенный (`cam.cpp`), а не внешний. |
| **Стратегия `Perimeter`** | Один замкнутый проход по периметру верхней грани (по умолчанию). |
| **Стратегия `FaceZigzag`** | Змейка по всей верхней плоскости: проходы вдоль X, переходы по Y у краёв. |
| **Stepover (шаг проходов)** | Расстояние между соседними проходами змейки; здесь `0.7 × диаметр фрезы`, чтобы полосы перекрывались. |
| **Вершина (corner)** | Точка исходной траектории; на ней цель удерживается, пока TCP не подойдёт на 0.1 мм, и не меньше 500 мс — фреза останавливается. |
| **Шаг, мм** | Расстояние между соседними подточками при интерполяции. |
| **Скорость (подача), мм/с** | Темп прохождения подточек; время на подточку = шаг ÷ скорость. |
| **`MaxSpeedDeviation`** | Параметр `EGMActPose`, ограничивающий скорость коррекции; иначе действует низкий лимит по умолчанию. |
| **`robtarget`** | Позиция робота в RAPID: `[[x,y,z],[q1,q2,q3,q4],…]`. |
| **Кватернион** | Способ задания ориентации 4 числами; в EGM — `EgmQuaternion` (`u0..u3`). |
| **protobuf** | Google Protocol Buffers: бинарный формат сериализации по схеме `.proto`. |
| **`.proto`** | Текстовое описание сообщений: имена, номера полей, типы. |
| **`protoc`** | Компилятор схем: генерирует код (C/C++/…) из `.proto`. |
| **Тег (tag)** | Номер поля в потоке protobuf; имена полей в данные не попадают. |
| **varint** | Способ кодирования целых в protobuf (переменная длина). |
| **proto2 / proto3** | Две версии синтаксиса. У ABB — proto2 (`required`), у нас — proto3 (`optional` для presence). |
| **Explicit presence** | Возможность явно передать значение по умолчанию (ноль) — в proto3 достигается меткой `optional`. |
| **nanopb** | C-реализация protobuf с фиксированной памятью; генерирует структуры и `pb_encode/pb_decode`. |
| **`max_count`** | Опция nanopb: максимальное число элементов `repeated`-поля (у нас 6). |
| **`pb_ostream_t` / `pb_istream_t`** | Потоки ввода-вывода nanopb для кодирования/декодирования из буфера. |
| **MSVC** | Компилятор Microsoft C/C++ (`cl.exe`), toolset v143/14.44 в VS2022. |
| **MSBuild** | Система сборки Microsoft, исполняет `.vcxproj`/`.sln`. |
| **CMake** | Генератор систем сборки: из `CMakeLists.txt` делает `.sln`, Ninja- или Make-файлы. |
| **Ninja** | Быстрый драйвер сборки; используется пресетами VS по умолчанию. |
| **UDP** | Протокол без гарантии доставки; EGM использует его ради минимальной задержки. |
| **Winsock** | Windows Sockets API (`ws2_32.lib`): `socket`, `bind`, `recvfrom`, `sendto`. |
| **loopback** | Адрес `127.0.0.1` — обмен внутри одной машины; так работает симуляция в RobotStudio. С реальным контроллером адрес ПК задаётся в `SIO.cfg` → `UCdevice` → `RemoteAdress`. |
| **`WSAEADDRINUSE` (10048)** | Порт уже занят — типичная ошибка при втором экземпляре приложения. |
| **Удержание (dwell)** | Время, в течение которого точка удерживается перед переходом к следующей. |
| **`.rspag`** | Pack&Go архив RobotStudio (обычный zip): станция + система + RAPID + бэкапы. |
| **RobotWare** | ПО контроллера ABB (в проекте встречаются 6.08 и 6.13). |
| **RobotStudio** | Среда ABB для моделирования и программирования; содержит виртуальный контроллер. |
