# Инструкция оператору: Git → Windows → STL → RobotStudio / ABB

Ветка: `feature/stl-opencamlib`. Все команды ниже вводятся в **PowerShell** на
Windows, по порядку. Если команда завершилась ошибкой, дальше не переходите.
Для сборки нужны Git, Visual Studio 2022 с компонентом **Desktop development with
C++**, Windows SDK, CMake и `tar`. Сборка — x64 / Release.

Демонстрационный перенос рассчитан для виртуальной станции **IRB1600-10/1.45**,
`toolPencil`, TCP `[0,0,280]`, home `[750,0,600]`. Это не измеренная калибровка
физической детали. Сначала выполните проверку в RobotStudio. На физическом ABB
запуск допустим только после проверки установленного инструмента, размещения,
досягаемости и свободного пути ответственным оператором; демо-перенос автоматически
на реальный стенд не переносится. Программа не управляет шпинделем или ориентацией.

## 1. Получить код

Если репозиторий уже есть, перейдите в его корень (пример пути замените своим):

```powershell
cd C:\Work\frezerovanie_sirius
git status --short
git fetch origin
git switch feature/stl-opencamlib
git pull --ff-only origin feature/stl-opencamlib
git rev-parse HEAD
```

`git switch` при первом использовании сам создаёт локальную ветку с отслеживанием
одноимённой `origin/feature/stl-opencamlib`. Если `git status` показывает чужие
изменения или переключение не удалось, не используйте `reset --hard`/`clean`.
Сохраните свою работу либо создайте отдельную копию:

```powershell
cd C:\Work
git clone --branch feature/stl-opencamlib https://github.com/estnafinema0/frezerovanie_sirius.git frezerovanie_sirius_cam
cd frezerovanie_sirius_cam
```

После каждого обновления ветки повторите сборку приложения и тесты из шага 3.
Сборку зависимости из шага 2 достаточно выполнить один раз, пока её версия не меняется.

> **Текущая рабочая копия** лежит в `D:\developments\DSH_workspaces\freza_sirius`
> (раньше — в `pullGitHub`) и **не является git-репозиторием**: папка `.git` при
> переносе не копировалась. Поэтому шаг 1 для неё не нужен, а тест
> `freza_protected_baseline` в ней пропускается с пояснением. Команды `git` ниже —
> для получения кода из GitHub на новой машине.

## 2. Собрать OpenCAMLib

Из корня полученного репозитория:

```powershell
cd VisualStudio\FrezaEgm
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build_opencamlib.ps1 -Configuration Release
```

`Bypass` относится только к этому процессу PowerShell и не меняет системную
политику. Скрипт загружает закреплённый исходный OpenCAMLib и проверенный архив
Boost, затем собирает DLL тем же MSVC. Результат находится в
`VisualStudio\FrezaEgm\out\deps\ocl-Release`.

`cmake` и `git` искать в `PATH` не нужно (но `git` и `tar` должны быть установлены):
скрипт сам находит `cmake` внутри VS2022. Если загрузка архива Boost падает на TLS
(`schannel`), скрипт повторяет её через `curl.exe`. Второй запуск скрипта безопасен:
готовые каталоги он не перезаписывает, а только проверяет версию и контрольную сумму.

Если скрипт обнаружил изменения в уже существующей зависимости, не стирайте их.
Можно использовать новый каталог, например `-Root C:\Work\freza-cam-deps`, и затем
указать этот путь в переменной `$deps` в следующем шаге.

## 3. Собрать приложение и проверить без ABB

Всё ещё в `VisualStudio\FrezaEgm`:

```powershell
$cmake = "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"
$ctest = "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe"

& $cmake -S . -B build-cam -G "Visual Studio 17 2022" -A x64 -DFREZA_ENABLE_CAM=ON
& $cmake --build build-cam --config Release --parallel 4
& $ctest --test-dir build-cam -C Release --output-on-failure
```

`CMAKE_PREFIX_PATH` и `BOOST_ROOT` подставлять не нужно: при собранном `out\deps`
CMake включает CAM сам. Если VS собирает папку через пресет `x64-release`, CAM там
тоже включается автоматически, а `libocl.dll` копируется рядом с exe.

Ожидаются три успешных CTest: `freza_selftest` (включает UDP-loopback),
`freza_regression` (73/73 при CAM ON, 46/46 при OFF), `freza_protected_baseline`
(в копии без `.git` он пишет «Protected baseline skipped» и считается пройденным).
Во время теста не запускайте EGM в RobotStudio и не подключайте обмен физического
контроллера. Порт 6510 должен быть свободен; закройте другой экземпляр FrezaEgm.

Отдельная проверка сборки без CAM, OpenCAMLib для неё не нужен:

```powershell
& $cmake -S . -B build-no-cam -G "Visual Studio 17 2022" -A x64 -DFREZA_ENABLE_CAM=OFF
& $cmake --build build-no-cam --config Release --parallel 4
& $ctest --test-dir build-no-cam -C Release --output-on-failure
```

## 4. Где файлы и как запустить программу

Вставлять STL в исходный код или в RAPID не нужно. Для своей модели можно создать
папку и скопировать файл в неё, либо открыть файл прямо из любого доступного каталога.
Пробелы и кириллица в пути поддерживаются.

```powershell
New-Item -ItemType Directory -Force .\data\user | Out-Null
# Необязательно: замените исходный путь своим, затем уберите #:
# Copy-Item 'C:\Users\Operator\Downloads\Моя деталь.stl' '.\data\user\Моя деталь.stl'

# Запуск CAM-версии:
.\build-cam\Release\FrezaEgm.exe
```

Контрольная модель уже в репозитории: `data\cam\Primer1.STL` (binary) и
`data\cam\Primer1-ascii.stl` (ASCII). Выбирать для первого запуска нужно одну из них.
Рядом с `FrezaEgm.exe` должен находиться `libocl.dll`: CMake копирует его сам.
Не переносите только EXE без DLL. Проще запускать из каталога сборки.

В открытом окне:

1. Нажмите **«Демо 20×20»**. Это выставит мм, масштаб 1 и перенос
   X=750, Y=0, Z=599.5. Проверьте **диаметр 4 мм**, **шаг CAM 0.5 мм**.
2. Нажмите **«STL → рассчитать…»**, выберите `data\cam\Primer1.STL`.
   Можно также перетащить один STL в окно или выбрать `.stl` в **«Открыть файл…»** —
   все три пути запускают один и тот же CAM-расчёт. Если единицы STL не выбраны,
   программа спросит, считать ли модель в мм; если не заполнен перенос XYZ —
   предложит демо-размещение `[750, 0, 599.5]`.
3. Проверьте предпросмотр: размер **20×20×0.5 мм**, **168 контактов OCL**,
   **5 итоговых точек**, границы в базе **[750,0,600]..[770,20,600]**.
   Нажмите OK, чтобы принять траекторию. Сам расчёт движения не запускает.
4. **«Сохранить CSV…»** → выберите, например, `data\user\Primer1-result.csv`.
   Формат остаётся `index,x,y,z`. Готовый эталон: `data\cam\Primer1-base.csv`.
5. В блоке EGM оставьте прежний порт **6510**, период **4 мс**. Для контрольного
   расчёта интерполяция включена, шаг **2 мм**, скорость **50 мм/с**:
   получится **41 точка** и 5 вершин. Шаг CAM и шаг интерполяции — разные параметры.

Первое открытие программы автоматически загружает старый квадрат 100×100 из
`data\trajectory.gcode`. До нажатия «Запустить траекторию» убедитесь, что вы
приняли именно STL-результат: **5 точек** и указанные выше границы.

Программа принимает только прямоугольный блок из **12 треугольников**, с гранями
параллельно осям детали. Произвольную модель, отверстия, наклон или даже более
подробную триангуляцию пока отклоняет. При ошибке прежняя траектория остаётся.
Поэтому после ошибки нельзя считать, что новая модель уже загружена.

### Своя деталь: перенос под home и STL из КОМПАС-3D

Первая точка CAM-пути — угол верхней грани блока плюс перенос, и она обязана
совпасть с `home` `[750, 0, 600]`: подвода от home нет. Формула переноса:

* `X = 750 − min.x`, `Y = 0 − min.y`, `Z = 600 − max.z`

где `min.x/min.y` и `max.z` — габариты STL в системе детали (после масштаба).
Для куба 100×100×100 с углом в начале координат это `X=750, Y=0, Z=500`
(верхняя грань на Z=100 → 600). Если КОМПАС построил деталь симметрично
(`min.x = min.y = −50`), то `X=800, Y=50, Z=500`.

Если при нажатии «Запустить траекторию» появляется сообщение о несовпадении с home,
программа сама считает нужный перенос, подставляет X/Y/Z в блок «STL / OpenCAMLib»
и показывает значения. После этого нажмите «STL → рассчитать…» и выберите тот же
STL: перенос применяется только при новом расчёте.

STL — это только сетка, траектории внутри нет: маршрут строит CAM по верхней грани
блока — по периметру или змейкой по всей плоскости (см. ниже). В КОМПАС-3D: деталь →
эскиз-прямоугольник на XY → «Операция выдавливания» → `Файл → Сохранить как… → STL`,
без фасок, скруглений и отверстий.

### Вся верхняя поверхность (змейка)

Галочка **«Вся верхняя поверхность (змейка)»** в блоке «STL / OpenCAMLib» меняет
стратегию: вместо одного прохода по периметру фреза обрабатывает всю верхнюю грань
змейкой. Шаг между проходами — **0.7 × диаметр фрезы** (при Ø4 проходы идут через
2.5–2.8 мм; последний проход всегда по дальнему краю). Фреза идёт центром по
верхней плоскости, половина диаметра на краю уходит за деталь, поэтому кромка
снимается полностью.

* `Primer1` 20×20, Ø4: 9 проходов, 18 точек, 378 контактов.
* куб 100×100, Ø4: 37 проходов, 74 точки, 7474 контакта, расчёт ≈0.1 с.
* маршрут начинается в том же углу, что и периметр: требование «начало = home»
  и расчёт переноса XYZ не меняются;
* каждый разворот — вершина траектории, а на вершинах фреза останавливается на
  0.5 с, поэтому обработка всей поверхности идёт заметно дольше контура
  (куб 100×100 при подаче 50 мм/с — порядка двух минут).

Без галочки поведение прежнее: один замкнутый проход по периметру. Стратегия
выбирается в момент расчёта; чтобы её сменить, нажмите «STL → рассчитать…» заново.

## 5. Проверить в действующей RobotStudio

1. Откройте существующую станцию **IRB1600-10/1.45**. Не создавайте новую станцию
   IRB120. Не меняйте `toolPencil`, home, `corr_frame`, порт или управление осями.
2. Если рабочий `ModuleEGM` уже загружен, оставьте его. Если модуль отсутствует,
   в RobotStudio: **RAPID → Modules → Add Module → File…** и выберите
   `<корень репозитория>\RobotStudio\ModuleEGM.mod`.
   STL и CSV в RobotStudio не загружаются — их читает FrezaEgm на ПК.
3. Сначала повторите знакомую старую траекторию 100×100, затем остановите сессию.
   Для STL повторите шаг 4 выше, проверьте первую цель `[750,0,600]`.
4. В **FrezaEgm** нажмите **«Запустить траекторию»**.
   Ожидаемое состояние: **«ожидание контроллера»**.
5. В **RobotStudio** выполните **PP to Main**, затем **Start**. RAPID сначала
   переместит TCP в home, затем начнётся EGM. Ожидается один замкнутый квадрат
   20×20 на Z=600 и возвращение в `[750,0,600]`, без поворота инструмента.
6. Следите за «Цель», «Факт. поза», счётчиками, MCI и журналом. По завершении
   нажмите **«Стоп»** в FrezaEgm. Для повтора создайте новую RAPID-сессию:
   **PP to Main → Start**, снова запустив ожидание в приложении.

Во время активной передачи импорт STL/CSV/координат заблокирован. Остановите
сессию перед заменой источника. Home и ручные команды остались прежними:
Home — первая точка загруженного файла; dX/dY/dZ считаются от неё.

## 6. Физический ABB

Сохраните действующую проверенную сетевую и контроллерную конфигурацию. Эта ветка
не требует новой загрузки RAPID, смены TCP, портов, адресов или настройки ориентации.
Приложение отвечает на первый пакет контроллера по прежнему механизму.

После локального CTest и успешного прогона в RobotStudio ответственный оператор
проверяет соответствие физического стенда существующей станции и фактическое
размещение детали. Если оно не соответствует демо-переносу, не запускайте
`Primer1-base.csv` на стенде как готовую калиброванную траекторию. Для CAM-пути
первая точка должна совпасть с текущим home; автоматического подвода от home нет.
Дальнейший пуск — по действующему регламенту стенда: загрузить и проверить результат
на ПК, включить ожидание в FrezaEgm, затем запустить существующую RAPID-программу.
Из CI и этого репозитория подтверждение физической совместимости не следует.

## 7. Если нужно только рассчитать CSV

Из `VisualStudio\FrezaEgm`, без GUI и без открытия UDP:

```powershell
# периметр (по умолчанию)
.\build-cam\tests\Release\FrezaEgm_cam_cli.exe `
  .\data\cam\Primer1.STL .\data\user\Primer1-result.csv mm 1 4 0.5 750 0 599.5

# вся верхняя плоскость змейкой: 11-й аргумент face
.\build-cam\tests\Release\FrezaEgm_cam_cli.exe `
  .\data\cam\Primer1.STL .\data\user\Primer1-face.csv mm 1 4 0.5 750 0 599.5 face
```

Родительский каталог `data\user` создайте командой из шага 4.
Аргументы после путей: единицы, масштаб, диаметр, шаг CAM, перенос X/Y/Z;
необязательный последний — `face` или `perimeter`.
Чтобы получить координаты **в системе детали**, укажите перенос `0 0 0`;
такой CSV нельзя отправлять в ABB как базовые координаты.
