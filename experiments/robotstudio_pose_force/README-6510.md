# Один T_ROB1 для IRB 1600-10/1.45

## Что запускать

Для испытания распакуйте Sirius-EGM-6510.zip в отдельный каталог Windows. На одном ПК работают RobotStudio с виртуальным IRC5 и MillingVirtualEgm. В комплекте — исходники C++17, Eigen, nanopb, сгенерированные сообщения проекта, RAPID, тесты и примеры CSV. Комплект использует вашу существующую станцию FrezaEGM.rssln. В самом репозитории файлы модуля и адаптера находятся в experiments/robotstudio_pose_force.

## 1. Сборка и проверка до запуска станции

В PowerShell из корня распакованного комплекта (Visual Studio 2022 с компонентом Desktop development with C++, CMake и Python 3):

~~~powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
$exe = ".\build\Release\MillingVirtualEgm.exe"
& $exe --check-poses .\smoke.poses.csv
~~~

Закройте другие программы, слушающие 6510, на время сетевого теста. CTest подменяет контроллер локальным UDP-процессом. В тесте он возвращает предыдущую команду как измеренную позу. Тест проверяет изменение XYZ и ориентации, нормальное окончание и обрыв связи до последней точки. Механика робота появляется на следующем этапе.

## 2. Подготовка копии станции

1. Откройте отдельную копию FrezaEGM со своим виртуальным контроллером. В резервной копии BACKINFO/backinfo.txt указаны VIRTUAL_USE, IRB 1600-10/1.45, 689-1 Externally Guided Motion, UDPUC Driver и RobotWare 6.08.01.00. В system.xml установки указан пакет 6.08.1040.
2. В Controller → Configuration → Communication → Transmission Protocol проверьте UCdevice, тип UDPUC, Remote Address 127.0.0.1, Remote Port Number 6510. Если меняли конфигурацию, перезапустите VC. В Motion → External Motion Interface Data проверьте конфигурацию default. Запустите моделирование в реальном масштабе времени (1×).
3. В копии T_ROB1 выгрузите прежний программный модуль с процедурой main и загрузите MillingPose6510.mod. Выполните Check Program. В Program Data задайте virtualConfirmed=TRUE. Для smoke оставьте runSeconds=5. Включите Motors On и установите PP to Main. Для прогона достаточно одной motion task.
4. Стартовое положение TCP в системе базы — (750, 0, 600) мм, ориентация ABB [0,1,0,0]. У simTool вылет 280 мм по Z фланца, как у демонстрационного карандаша станции. Убедитесь в копии станции, что стартовый MoveJ проходит свободно и выбран правильный механизм. Для визуальной проверки коллизий настройте Collision Set инструмента и робота с оснасткой и заготовкой. Шпиндель в программе не включается.

## 3. Первый прогон

~~~powershell
& $exe --pose-only-6510 --anchor-first-to-feedback .\smoke.poses.csv
~~~

После строки ready запустите T_ROB1 в режиме одного цикла. ПК ждёт первый валидный EgmRobot до 30 с, включая время стартового MoveJ. При таймауте остановите цикл, верните PP to Main и повторите. Первой целью ПК возвращает полученную позу TCP. Далее за две секунды TCP проходит 2 мм по +X, затем 2 мм по +Y. Относительно стартовой позы ориентация инструмента поворачивается на 4° вокруг оси Y базы. При заданном simHome ожидается (752, 2, 600) мм и кватернион приблизительно [0, 0.999391, 0, -0.0348995] с точностью до общего знака.

На ПК сравниваются измеренная конечная позиция и ориентация с командой. Для успешного окончания требуется удержание в пределах 0.1 мм и 0.5° в течение 0.2 с, затем прекращение потока. Проверьте также штатное завершение T_ROB1 после EGMStop, EGMWaitCond и EGMReset и отсутствие ошибок в Event Log. Один только обрыв UDP после достижения цели не подтверждает штатное окончание RAPID. Для оценки всей траектории посмотрите след TCP и ориентацию во время движения.

## 4. Траектория вашего планировщика

В MillingAnalyzer экспортируйте pose CSV целой грани или program.poses.csv из расчёта программы. Адаптер различает штатные заголовки. В архив включён face-8.poses.csv, рассчитанный MillingAnalyzer из приложенного stepped-solid.step. Сначала проверьте выбранный файл, затем запустите адаптер.

~~~powershell
& $exe --check-poses .\face-8.poses.csv
& $exe --pose-only-6510 --anchor-first-to-feedback .\face-8.poses.csv
~~~

Задайте в T_ROB1 число runSeconds из строки запуска ПК, затем запустите RAPID. Для приложенной грани это 18 с. Интервал равен округлённой вверх длительности CSV плюс 3 с на установление. Программный таймер RAPID ограничивает сеанс даже при непрерывном потоке. CondTime определяет длительность выполнения условия сходимости ABB и вынесен за пределы этого окна. При паузе или изменении скорости моделирования повторите опыт с начала.

CSV задаёт время в секундах, положение в мм и абсолютную ориентацию в системе детали как qw,qx,qy,qz. Задание берётся по времени, XYZ интерполируются линейно, ориентация — SLERP. Один пакет обратной связи запускает один ответ. В EgmSensor.planned.cartesian передаются pos.x/y/z и orient.u0/u1/u2/u3 в порядке w,x,y,z, включая нулевые поля. ПК отвечает на адрес и исходный порт принятого EgmRobot. Период 4 мс запрашивается у VC. Реальный период зависит от среды.

Обе системы EGM заданы как EGM_FRAME_BASE с единичной позой. Для показа адаптер совмещает первую позу детали с первым feedback и печатает перенос и кватернион размещения детали. Планировщик направляет +Z к хвостовику, у демонстрационного TCP +Z идёт к кончику. Используется q_base_TCP = q_base_part × q_part_cutter × Rx(180°). Для проверки взаимного положения разместите CAD в станции по напечатанному преобразованию. Фактическое положение детали и реальные tooldata шпинделя предстоит определить отдельно.

Адаптер отклоняет отмеченные планировщиком коллизии, разрывы последовательности, слишком большие приращения и участки быстрее 50 мм/с или 30°/с. Длительность одного теста ограничена 240 с. При отсутствии feedback более 0.5 с до достижения конечной позы адаптер сообщает об ошибке. Если робот остаётся неподвижным, проверьте Check Program, PP, virtualConfirmed, имя UCdevice, порт и первый пакет. Если движение закончилось раньше, проверьте runSeconds, масштаб времени и журнал контроллера.

## Границы проверки и источники

Сборочные и геометрические проверки выполнялись на macOS. Для face-8 получены 213 исходных поз и 3655 проверенных бинарных команд за расчётные 14.614 с. Запуск RobotStudio, проверка RAPID в RW 6.08 и измерение частоты UDP остаются этапами испытания в Windows. Для оценки механики нужны проверка достижимости, конфигурации осей и коллизий с реальной геометрией. Испытание не оценивает усилие резания.

Команды сверены с ABB Application manual — Externally Guided Motion, RW6, 3HAC073319-001, разделы EGM Position Guidance, UdpUc, EGMActPose, EGMRunPose, EGMStop, EGMWaitCond. Приложенное руководство 3HAC098387 описывает RAPID RW8.2. Руководство Force Control Standard относится к RW8, остальные материалы о датчике относятся к монтажу и силовому контуру.
