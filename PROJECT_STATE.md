# Обновление: обработка всей верхней грани (змейка), 22.11.2026

Добавлена вторая CAM-стратегия `cam::Strategy::FaceZigzag`: фреза проходит всю верхнюю
плоскость блока змейкой, а не только по периметру. Шаг проходов — `0.7 × диаметр`
(`Options::stepoverFactor`), последний проход по дальнему краю, центр торца идёт по
верхней плоскости. Каждый проход проверяется настоящим `ocl::PathDropCutter`;
`ValidatePath` проверяет движение по идеальной змейке, габарит и `шаг ≤ D`.

* GUI: галочка «Вся верхняя поверхность (змейка)» в блоке «STL / OpenCAMLib»;
  по умолчанию выключена — прежний периметр.
* CLI: 11-й аргумент `face` или `perimeter`.
* Числа: Primer1 20×20, Ø4 — 9 проходов, шаг 2.5 мм, 18 точек, 378 контактов;
  куб 100×100, Ø4 — 37 проходов, шаг 2.78 мм, 74 точки, 7474 контакта, расчёт 0.13 с.
* Проверки: `freza_regression` теперь 73/73 (добавлено 7 проверок змейки),
  3/3 CTest в `build-cam`, `build-vs`, `out/build/x64-release`.
* Ограничения те же: только замкнутый прямоугольный блок, одна плоскость Z, без
  карманов, смещения на радиус и слоёв по глубине. Каждый разворот — вершина,
  поэтому остановка 0.5 с на вершине делает обработку поверхности медленнее контура.

# Обновление: рабочий STL/CAM на Windows, 21.11.2026

Ветка `feature/stl-opencamlib` (на тот момент проект лежал в `pullGitHub`, сейчас — в корне рабочей области). Сборка MSVC 2022
x64 с настоящим OpenCAMLib. Что было не так и что исправлено:

* `tools/build_opencamlib.ps1` теперь сам находит `cmake` внутри VS2022 (в `PATH` его
  нет) и повторяет загрузку архива Boost через `curl.exe`, если `Invoke-WebRequest`
  падает на TLS.
* `cmake/Cam.cmake` сам находит `out/deps/ocl-Release` и `out/deps/boost_1_87_0` и
  включает CAM, когда зависимость собрана; без неё поведение прежнее (CAM OFF,
  координаты/CSV/EGM работают). `CMAKE_PREFIX_PATH`/`BOOST_ROOT` не обязательны.
* «Открыть файл…» принимает `.stl`: расширение распознаётся до парсера, поэтому
  сообщение «в файле найдено меньше двух точек траектории» больше не появляется.
  Если не выбраны единицы или не задан перенос XYZ, программа спрашивает, а не
  выдаёт техническую ошибку (`app_window.cpp`).
* `FrezaEgm.exe` в трёх деревьях собран с CAM: `build-vs` (решение VS2022,
  пересоздан — старый кэш был от прежнего пути), `build-cam` (по документации),
  `out/build/x64-release` (пресет VS/Ninja). `libocl.dll` лежит рядом с exe.
* `tests/protected.cmake` больше не считает нарушением автосейв станции
  `RobotStudio/FrezaEGM/Stations/*.rsautosave`: RobotStudio удаляет и перезаписывает
  его при каждом открытии станции, из-за чего проверка ложно падала. Остальные файлы
  `RobotStudio` (RAPID, станция, конфигурация) по-прежнему защищены.
* Точность углов: `ReadSettings()` в `app_window.cpp` задаёт `reachToleranceMm = 0.1`
  (было 1.5 мм — из-за этого цель уходила на следующую сторону, не дойдя до вершины,
  и квадрат рисовался со срезанными углами) и `cornerSettleMs = 2000`. Протокол,
  сериализация и RAPID не менялись; см. ADR-015 в `docs/09-decisions.md`.
* Остановка на вершинах: `OnStartTrajectory` поднимает удержание каждой вершины до
  **500 мс** (`kCornerStopMs`), поэтому фреза сначала встаёт и только потом идёт к
  следующей точке. Без интерполяции все точки передаются с удержанием 1 с и флагом
  вершины — клиент ждёт фактического прихода. Проверка «дошёл» одного допуска 0.1 мм
  недостаточно: она срабатывает, пока TCP ещё движется.

Проверено локально 21.11.2026: **3/3 CTest** в каждом из трёх деревьев
(`freza_selftest` с UDP-loopback, `freza_regression` 66/66 на 21.11 и 73/73 после добавления змейки, `freza_protected_baseline`),

## Что уже работает

* **Симуляция в RobotStudio 6.08.01**: робот IRB 1600 встаёт в `home` (750, 0, 600)
  кончиком инструмента `toolPencil` и проходит **замкнутый квадрат 100×100 мм**
  (5 точек, 201 подточка при шаге 2 мм), возвращается в начало.
* **Скорость регулируется** слайдером/полем «скорость, мм/с» (5–200) и реально влияет
  на движение; шаг меняет только гладкость.
* **Обратная связь** в приложении: состояние, номер точки, цель (абсолютная поза TCP),
  фактическая поза, счётчики пакетов, MCI, моторы, сходимость.
* **Ручные команды**: `dX/dY/dZ` от первой точки и кнопка `Home (0, 0, 0)`.
* **CSV**: «Сохранить CSV» / «Загрузить CSV» — сохранение массива точек и загрузка его
  как источника траектории (требование задания, шаги 3–4).
* **Самотест без робота**: 35 проверок (файл → точки → CSV → интерполяция → protobuf →
  UDP-loopback), `ctest` проходит.

## Ключевые ошибки, которые уже пройдены (чтобы не повторять)

| Симптом | Причина | Решение |
|---|---|---|
| `50456 Close to singularity`, моторы OFF | `home` (750, 0, 300) с инструментом вверх | `home` (750, 0, 600), ориентация `[0,1,0,0]` |
| Робот едет «к себе и вниз», не доезжает | отправлялись смещения, а контроллер ждёт абсолютную позу | абсолютные координаты TCP |
| Инструмент заворачивается, уходит с траектории | включены `\Rx \Ry \Rz` при единичном кватернионе | убрать повороты |
| Трапеция вместо квадрата | цель переключалась по таймеру, робот не успевал | досылка на вершинах |
| Скорость не реагирует на настройку | низкий лимит `MaxSpeedDeviation` по умолчанию | `\MaxSpeedDeviation:=1000.0` |
| Движение «стоп-разгон» на каждой подточке | ожидание достижения каждой подточки при мелком шаге | на прямых цель движется по времени |
| `Состояние EGM: ошибка` в конце | контроллер закрывает сессию после `EGMReset` (WSAECONNRESET) | штатное завершение сессии |
| `Reference to unknown entire data toolPencil` | `toolPencil` — графика, а не `tooldata` | объявлен `PERS tooldata toolPencil` |

## Возможные следующие шаги

1. Управление ориентацией инструмента (кватернион в `EgmSensor` + `\Rx \Ry \Rz`,
   с корректной опорной ориентацией).
